# 视觉参照 — "好看"在这个产品里长什么样

**打开这几张图，看一眼。** 然后再读 `../examples/design-reference/source/style.css`。

代码能教结构，教不了品味。1000 行 CSS 能推导出"这里该用 14px 正文"，推不出
"这个界面读起来像一张卡片还是像一个产品"。这个文件夹补的就是后半截。

这些图都是本仓库自己的 MiniApp，由 `npm run shoot:miniapp` 渲染——**不是设计稿，
是真实运行结果**，所以图上的每一处都对应着仓库里可以读到的 CSS。

| 图 | 看什么 |
|---|---|
| `celestial-atlas-dark-zh-CN.png` | **天花板在这张。** 自持色板 + 衬线显示字 + 场景随选中天体染色 + 高密度数据面板，四样同时成立而不打架。注意它把强调色压到极低占比——数据是内容，颜色只负责指路。 |
| `showcase-dark.png` | 自持色板的另一种样子：暖奶油纸面配玫瑰金，一个 motif（压边）贯穿卡片、按钮、标签。注意留白——它没有用装饰填满空白，这是"贵"和"廉"最直接的分界。 |
| `signal-chart-dark-zh-CN.png` | 数据密度高但仍然安静。等宽数字让一列数字对齐；网格线淡到几乎看不见但拿掉就散；强调色只落在两条曲线和选中态上，没有渗进坐标轴文字。 |
| `form-desk-light-zh-CN.png` | 密集表单。分组清楚、错误信息在它发生的地方、必填与可选不靠颜色区分。浅色下每个层次都还站得住——深色好看不难，浅色好看才需要重新调一遍。 |

## 怎么用

生成新 MiniApp 之前，**先看图，再决定调性**，然后去读最接近形态的那个
`../examples/<名字>/`。

- 想要展示型 / 天花板 → 看 `celestial-atlas`、`showcase`
- 想要工具型 → 看 `form-desk` / `signal-chart`
- 只想要骨架和动效 → 读 `../examples/design-reference/source/style.css`

**看到"还是廉价"的时候，回去改那一处，不要整体重写。** 参考图是用来对照的，
不是用来临摹的——临摹出来的东西一眼就是临摹的。

## 这三张图不包括什么

- **深色容易好看，浅色难。** 四张里三张是深色。别把"深色好看"当成通用结论。
- **截图是静止的。** 动效、进场、翻牌这些只能从代码读，看图看不出来。
- **没有"很丑"的对照。** 反面样本比正面样本更有用，但仓库里没有
  故意做坏的样例——拿真实用户产物当反面教材会泄露用户数据。

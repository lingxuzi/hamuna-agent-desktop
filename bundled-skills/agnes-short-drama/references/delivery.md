## Part 2：迭代修改协议

### 2.1 修改范围与回退层级

| 修改内容 | 回退层级 | 重新生成范围 |
|---------|---------|-------------|
| 单镜头 prompt 文案 | Phase 5 单镜 | 仅该镜头 |
| 镜头顺序调整 | Phase 5 单镜 | 仅该集 |
| 角色/场景/道具资产图 | Phase 4 资产库 | 该资产 + 所有引用镜头 |
| 风格锚定词 | Phase 1 + Phase 4 + Phase 5 | 全项目重生 |
| 剧情/世界观/角色设定 | Phase 2 | Phase 3-5 全链路重生 |
| 集数调整 | Phase 2 + Phase 3 | 重新生成新增/删除的集 |

**关键原则**：尽量改最小层级，避免"一个错改全部"。

### 2.2 用户审片后的常见修改

**类型 A：单镜头不满意**

**诊断流程**：
1. 用户给出反馈："第 1 集第 4 镜头不好"
2. AI 复述："您是说 E01_Shot04_xxx.mp4 这个镜头吗？哪里不满意？"
3. 用户回答（角色不对 / 动作不对 / 光线不对 / 时长不对）
4. AI 针对性修改 prompt
5. 用 agnes-video-2.5-flash 重新生成
6. 用户复检

**修改 prompt 的常见操作**：
- 角色不对 → 修改 `[角色@]` 段，强化角色外观描述
- 动作不对 → 修改 `[动作]` 段，动词更精确
- 光线不对 → 修改 `[色调/光线]` 段
- 时长不对 → 改 seconds 参数（注意 ≤ 12s 上限）
- 落幅不对 → 修改 `[落幅]` 段

**类型 B：整集节奏问题**

**诊断流程**：
1. 用户给出反馈："第 2 集节奏太拖"
2. AI 复述："您是说 E02 集节奏要更紧凑吗？"
3. 用户确认（缩短单镜时长 / 增加镜头数 / 加速剧情）
4. 调整 Phase 5 单镜 prompt（如把每镜从 8s 缩到 5s）
5. 重新生成该集所有镜头
6. 重新合成 E02.mp4

**类型 C：风格问题**

**诊断流程**：
1. 用户给出反馈："整体风格我想换 2D 二次元"
2. AI 复述："您是说从悬疑电影风格换到二次元动漫风格？"
3. 用户确认 → 整体风格变更（**回退到 Phase 4**）
4. 重新生成所有资产图（角色/场景/道具 都要重出）
5. 重新生成所有分镜图
6. 重新生成所有单镜视频
7. 重新合成全集

**注意**：风格变更是最大成本的操作，应在 Phase 1 创意简报阶段就充分确认风格，**避免反复横跳**。

**类型 D：剧情问题**

**诊断流程**：
1. 用户给出反馈："第 3 集的反派动机不合理"
2. AI 复述："您是说 E03 反派 @玄慈住持 的动机需要调整？"
3. 用户确认修改方向
4. 回退到 Phase 3 → 调整 E03 剧本
5. 回退到 Phase 5 → 重新生成 E03 所有镜头
6. 重新合成 E03.mp4

## Part 3：失败处理（fail-fast 协议）

### 3.1 视频生成失败（agnes-video-2.5-flash）

**允许 retry 一次**：同一工具 + 同一参数再调一次。
第二次仍失败 → 立即停止，把 `video_id`（如有）和错误原样给用户。

### 3.2 禁止 fallback 的范围

**绝对不允许**通过改这些参数来"绕过错误"：
- 换工具 / 换 model / 换 size / 换 ratio / 换 seconds
- 减 `timeout_seconds` 或改 `poll_interval_seconds`
- 改 `images[]` 元素 / 改 `image_paths[]` 元素
- 改 `first_frame` / `last_frame`
- 改 prompt 语义（避开错误来临时改写 prompt 重试）

**为什么**：这些参数锁定是 fail-fast 协议的核心——避免因"绕过错误"导致最后产出与设计意图完全脱节。

### 3.3 用户反馈 vs 工具失败的区分

| 场景 | 处理 |
|------|------|
| 用户说"这个镜头不对" | 用户反馈 → 正常迭代 |
| agnes-video-2.5-flash 返回超时/错误 | 工具失败 → retry 1 次，失败则停止 |
| 模型生成内容与 prompt 偏差 | 用户反馈（产出问题） → 改 prompt 重生成 |
| 用户主动取消 | 立即停止当前任务 |

### 5.2 单集合成脚本

```bash
#!/bin/bash
# compile_episode.sh - 合成单集所有镜头

EPISODE=$1  # 例如 E01

cd shots/${EPISODE}

# 创建 concat 列表
ls *.mp4 | sort | sed "s/^/file '/; s/$/'/" > concat_list.txt

# 拼接
ffmpeg -f concat -safe 0 -i concat_list.txt \
  -c:v libx264 -preset slow -crf 18 \
  -c:a aac -b:a 192k \
  "../../final/${EPISODE}.mp4"

cd ../..
echo "✅ ${EPISODE} 合成完成: final/${EPISODE}.mp4"
```

## Part 6：用户沟通协议

### 6.1 不要主动展示的内容

- ❌ "我检测到您属于 Mode X"（参见 SKILL.md Phase 0）
- ❌ 工具调用细节（除非用户主动问）
- ❌ 大段技术原理（除非用户主动问）

### 6.2 必须主动汇报的内容

- ✅ **关键决策点**：风格选择、叙事模型、关键反转、角色动机
- ✅ **交付物状态**：每完成一阶段主动汇报（"Phase 3 完成，5 集剧本已生成"）
- ✅ **风险预警**：风格与题材冲突、时长超出上限、资产图异常等
- ✅ **修改影响**：告诉用户"改这个会触发 X 重生成"

### 6.3 关键确认节点（必须等待用户确认才能继续）

| 节点 | 等待确认内容 |
|------|-------------|
| Phase 1 完成后 | 需求表 + 风格选择是否正确 |
| Phase 2 完成后 | 世界观/角色/剧情概要是否合意 |
| Phase 3 完成后 | N 集剧本整体节奏与剧情是否合意 |
| Phase 4 完成后 | 资产图是否与角色/场景描述一致 |
| Phase 5 每集完成后 | 分镜图与单镜视频是否合意 |
| Phase 6 完成后 | 最终合成视频是否需要修改 |

### 6.4 防止"自作主张"

- ❌ 不要在没确认前直接进入下一 Phase
- ❌ 不要在用户没要求时主动重做已经通过的内容
- ❌ 不要替用户做关键决策（风格、角色动机、关键反转）
- ✅ 关键节点必须等用户确认
- ✅ 用户主动说"继续"才能进入下一阶段

## Part 7：交付后维护

### 7.1 用户二次创作

如果用户后续想：
- **加新集** → 回到 Phase 2，确认世界观/角色一致性，生成新集剧本
- **改某集结局** → 回到 Phase 3 该集，重出分镜与视频
- **改风格** → 回到 Phase 1，全项目重生
- **导出新比例**（9:16 → 16:9）→ 重新生成所有视频

### 7.2 项目归档建议

每个完成的短剧项目应该：
1. **备份到独立目录**：`projects/{项目名}_{日期}/`
2. **README.md 记录关键决策**：风格选择理由、关键修改点、用户反馈
3. **保留中间产物**：分镜图、资产图、单镜视频（用于后续修改）
4. **打 tag 标识完成状态**：`v1-final`、`v2-final`（用户迭代的版本）

### 7.3 复用资产

完成的短剧资产可以跨项目复用：
- 风格锚定词模板（直接复制）
- 角色资产图（如果新剧有相同角色）
- 场景资产图（如果新剧有相同场景）
- 道具资产图（如果新剧有相同道具）

复用时注意：**只复用风格匹配的资产**——3D 古风国漫的角色资产图不能直接套到 2D 二次元剧里。

## Part 8：错误日志与排查

### 8.1 常见错误速查

| 错误 | 原因 | 解决 |
|------|------|------|
| agnes-video-2.5-flash 超时 | 网络慢或模型负载高 | 等 30s retry，或调整 timeout |
| 生成的视频与 prompt 偏差大 | prompt 描述模糊 | 补全 12 字段，特别是 [落幅] 和 [动作] |
| 角色外观跨镜头不一致 | 没用资产图 reference | 重出资产图 + reference 模式重生成 |
| 场景色调跨集漂移 | 风格锚定词不统一 | 锁定全项目风格锚定词 |
| 单镜超过 12s | seconds 参数过大 | 拆 2 段，转场用叠画或闪白 |
| 合成 mp4 无法播放 | 音频时基不一致 | 重新编码音频 `-c:a aac -b:a 192k` |

### 8.2 错误排查清单

按顺序执行（成本从低到高）：

1. ✅ 检查 prompt 12 字段是否齐全
2. ✅ 检查资产图是否存在且清晰
3. ✅ 检查 reference images 数量 ≤ 3
4. ✅ 检查参数是否锁定（size 720P / seconds ≤ 12 / ratio 一致）
5. ✅ retry 一次（同一参数）
6. ⚠️ 如仍失败，向用户汇报原错误，**不自行 fallback**

### 8.3 资源追踪

每个视频生成记录应保留：
```
{video_id}：
  - prompt: <完整 prompt>
  - reference images: [<路径 1>, <路径 2>]
  - 参数: size/seconds/ratio
  - 生成时间: YYYY-MM-DD HH:MM:SS
  - 提交耗时: X 秒
  - 用户反馈: 通过/未通过
  - 重生成次数: N
```

这些记录便于：
- 复盘失败模式
- 优化后续 prompt
- 用户决策追溯

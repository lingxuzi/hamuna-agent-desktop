# 视频模型与生成段数路由

## 三个概念不得混用

- `成片时长`：最终广告需要多少秒；
- `视频模型`：本轮调用哪个当前平台可用模型；
- `生成段数`：一次生成完整成片，还是分成多次生成后剪辑。

某个模型只能生成 15 秒，不等于平台上所有模型都只能生成 15 秒。用户选择 30 秒，也不自动等于必须拆成两个 15 秒段。先确认当前入口的模型能力，再组合时长、模型与段数。

## 能力核对顺序

按以下顺序建立本轮的“平台能力快照”：
1. 当前 Agent 或平台实际返回的可用视频模型列表、时长选项、积分/价格和输入能力；
2. 当前平台的官方产品页、模型说明或界面可见参数；
3. 用户刚刚在该平台完成的实测结果；
4. 仍无法核实时，明确写 `【待确认：当前平台模型/时长/价格】`，不得凭旧版本经验补全。

能力快照至少记录：

| 字段 | 用途 |
| --- | --- |
| 模型显示名或 ID | 防止把不同版本混为一谈 |
| 单次原生最长时长 | 判断单段是否可行 |
| 参考图/视频/音频能力 | 判断素材能否直接输入 |
| 原生声音能力 | 判断旁白、音效和音乐能否同轮完成 |
| 质量、速度与稳定性 | 估计可用率和返工风险 |
| 当前价格或积分 | 计算本平台、本时点的性价比 |

模型价格、套餐、限额和可用入口会变化。未经本轮核对，不得写“某模型永远最便宜”或把旧价格当作当前事实。

## 推荐算法：先满足，再比性价比

1. 先按硬条件过滤：能否完成目标单段时长、所需参考素材、声音、画幅、质量和编辑要求；
2. 再比较总成本：单次价格只是其中一项，还要考虑预计生成段数、后期拼接和因连续性失败而重试的成本；
3. 在满足交付条件的候选中，推荐综合成本最低、可用率足够的方案；
4. 同时给一个更高质量或更高控制的备选，并说明代价；
5. 用户指定模型或段数时优先保留，只有组合不可执行时才提示冲突并让用户选择替代方案。

“性价比最高”指当前平台、当前任务下的综合判断，不等于列表中单次积分最低。

## 默认路由

### 15 秒

- Agnes 单次视频生成上限 10 秒，15 秒至少拆成 2 段（5s+10s 或 8s+7s）
- 默认使用 `2 段` 策略：按故事自然段拆分，每段写独立完整提示词
- 分段原则：不在同一镜头内跨场景，每段有独立开始态/结束态/剪辑接口
- 若任务简单（单一产品、单次动作），可考虑单段 10s + 收尾裁剪，但仍需明确标注

### 30 秒

- Agnes 单次视频生成上限 10 秒，30 秒至少拆成 3-6 段（每段 5-10s）
- 默认推荐分段策略：按故事自然段拆分，每段独立提示词 + 剪辑接口说明
- 分段优先级：① 场景切换 → ② 叙事段落 → ③ 人物关系转换
- 减少拼接风险的策略：相邻段共享环境声床、光色弧线延续、动作跨段连续

### 自定义秒数

- 按 Agnes 单次上限 10 秒拆段，不足 10 秒时尽量控制在单段内
- 超过 10 秒时必须拆分，按故事自然段而不是机械等分
- 每段写独立完整提示词、结束状态、声音交接和剪辑接口
- 拆分段数 = ceil(目标时长 / 10)

## 用户可选择的问法

把模型与段数作为两个独立选项，并与其他生成配置一次确认：

```text
4. 视频模型：使用推荐模型 / 指定模型。推荐会先读取当前平台可用列表，再按时长、素材、声音、质量与成本判断；
5. 生成段数：单段完整生成 / 多段生成后剪辑 / 按当前平台能力自动选择。单段连续性和自然运镜通常更好；多段便于局部重跑，但会增加人物、光色、声音和动作衔接风险。
```

如果平台已经明确返回模型列表，直接列出实际候选和推荐理由。平台未公开模型名时，只称“当前平台可用模型”，不得猜测底层版本。

## 冲突处理

| 用户选择 | 处理方式 |
| --- | --- |
| 15 秒 + 推荐分段 | 拆成 2 段（5s+10s 或 8s+7s），按故事自然段分段 |
| 30 秒 + 推荐分段 | 拆成 3-6 段，按场景/叙事分段，每段独立提示词 |
| 用户指定单段完成 30 秒 | 说明 Agnes 10s 上限，建议多段或裁剪至 10s |
| 用户指定分段数 | 尊重用户选择，按指定段数拆分 |
| 模型/平台能力不可见 | 标注待确认，不虚构参数；给出基于能力的暂定方案 |

不得静默更换用户指定段数，也不得把"直出/九宫格"误解为"单段/多段"。九宫格只是是否先做分镜预览；确认后的九宫格仍按 Agnes 10s 上限拆分生成。

## 输出最小信息

最终交付至少写明：

```text
平台能力快照：Agnes 单次视频上限 10s（已确认）
生成段数：X 段 × Ys（每段独立提示词）；选择理由
剪辑接口：每段结束态 → 下一段开始态 的描述
替代方案：只在确有价值时给出一项
```

# 关键帧生成 Ref

当剧本、分镜表和资产已获得用户确认/由用户提供，需要生成片段关键帧图时读取本文件。

## 目标

把确认后的资产和每集 6 个片段的分镜，转化为关键帧图 prompt 和关键帧图片。

每个 90 秒短剧单集默认生成 7 张关键帧：

1. `SEG01_START`：片段一第 1 秒画面。
2. `SEG01_END`：片段一最后 1 秒画面。
3. `SEG02_END`：片段二最后 1 秒画面。
4. `SEG03_END`：片段三最后 1 秒画面。
5. `SEG04_END`：片段四最后 1 秒画面。
6. `SEG05_END`：片段五最后 1 秒画面。
7. `SEG06_END`：片段六最后 1 秒画面。

## 澄清策略

关键帧生成前确认：

- 项目名、集数、画幅比例、统一画风。
- 要处理的具体集数 / 片段。
- 是否已有 6 个 12 秒片段（drama 单集默认 6 段 × 12s = 72s）。
- 角色、场景、道具参考图是否可用。
- 是否使用短剧默认竖屏比例 `9:16`。

如果缺少必要角色脸部 / 服装、场景空间 / 光影或关键道具资产，停止当前关键帧任务，返回 `assets.md`。

## 关键帧工具调用硬约束

- 关键帧生成默认必须使用 `image_to_image` / I2I。
- 只要已有角色、场景、道具资产图，生成关键帧时必须将相关资产图作为工具参考图参数传入，不能只在 Prompt 文本中描述或编号。
- 禁止在已有资产图的情况下使用纯 `text_to_image` 生成关键帧。
- 每次生成前必须先列出本张关键帧实际传入的参考图清单：动态编号（`[img0]`、`[img1]`、`[img2]`...）、资产名称、URL / 本地路径、用途。
- 生图 I2I Prompt 只能使用 `[img0]`、`[img1]`、`[img2]`... 引用输入图，禁止使用 `@图片`、`图1`、`参考图1` 等格式。
- 如果找不到必要资产图，必须停止关键帧生成并返回资产阶段补齐，不能自行脑补。

## 提取要求

每张关键帧都要：

- 找到对应片段和具体时刻。
- **参考图动态编号**：从已确认的角色、场景、道具资产中提取最合适的参考图，并作为 `image_to_image` / I2I 的工具参考图参数传入。将实际选出的参考图按顺序编号为 `[img0]`、`[img1]`、`[img2]`...，并在生图 Prompt 中严格使用这些编号指代。**绝不传入无关资产图**。
- 保持当前物理状态：湿衣服、伤痕、污渍、手持道具、面部紧张、光影、天气、色温等。
- 写清动作结果、表情、姿势、构图、景别、机位角度和剧情连续性。
- **五维物理表演（与 storyboard 阶段硬门控对齐）**：画面主体的表演描述严禁使用抽象情绪词（"难过 / 愤怒 / 委屈 / 绝望" 等），必须通过以下**至少 3 维度**呈现，特写尽量 5 维全覆盖：
  1. **微表情与视线**（瞳孔 / 睫毛 / 视线失焦 / 咬肌 / 嘴角肌理）
  2. **肢体与体态**（重心 / 双肩 / 指尖 / 指节 / 手腕）
  3. **动作中间态**（欲言又止 / 转身一滞 / 抬手悬空等未完成状态——AI 视频稳定性的核心约束）
  4. **生理应激**（喉结 / 鼻翼 / 额角青筋 / 眼睑 / 胸腔节律）
  5. **光影呼吸**（呼吸和体态变化带动皮肤与轮廓阴影实时位移，用 `ambient light drift`）
  完整规范见 `references/drama/storyboard.md` "五维物理表演（强制）"段。
- **运镜强度匹配景别**：特写 `tripod static shoot` / 中近 `subtle cinematic handheld` / 中远 `full-scale cinematic handheld`——参考 `references/drama/storyboard.md` "运镜按景别分级" 段。
- **全局风格锚点**：Prompt 开头必须加上整个项目统一的风格限定词（如 真人电影风格）。

## I2I 生图指令撰写规范

每张关键帧的 I2I Prompt 必须按“编辑目标 + 保留项 + 编辑项 + 空间线性描述 + 风格质量约束 + 画幅比例”组织，最终合并为一段连贯的话，不要输出“编辑目标：”“保留项：”等小标题。

- **编辑目标**：直接说明当前关键帧要基于哪些 `[imgX]` 完成什么画面生成，明确来源图片、目标状态和作用范围。
- **保留项**：明确参考图中必须保持不变的主体身份、角色脸部特征、服装结构、场景空间、构图关系、透视角度、光影方向、材质细节和道具特征。禁止只写“保持不变”“其他不变”“参考原图”。
- **编辑项**：逐项写清需要新增、替换、重绘、重排或状态变化的对象，例如角色动作、表情、站位、湿衣服、伤痕、手持道具、场景交互区变化等。
- **空间线性描述**：按从背景到主体、从主体到局部、从主要编辑区域到次要编辑区域的顺序描述画面；每个区域写清位置、原参考内容、保留项、编辑动作、目标结果和视觉约束。
- **多图约束**：若传入多张参考图，必须分别说明 `[img0]`、`[img1]`、`[img2]` 的用途和保留内容，不得使用“同上”“其余图片一样处理”等概括。
- **文字约束**：如关键帧涉及可见文字，必须逐条写清原文案与目标文案，所有文字用中文双引号 `""` 框定。
- **风格与质量约束**：写清整体风格、光线、色调、材质、阴影、真实度和融合要求，确保修改区域与参考图自然融合。
- **画幅比例**：每张关键帧 Prompt 结尾必须以比值格式写清画幅比例，例如 `9:16` 或 `16:9`。

## 片段关键帧 Prompt 规划表

| 关键帧类型 | 对应分镜位置 | 需引用的资产设定图（动态判断） | 必须写清的内容 |
|---|---|---|---|
| **SEG01_START** | 片段一 00:00 首帧 | 自行判断提取最合适的场景图（如全景/中景）及角色设定图 | 角色初始站位、动作起点、初始表情、道具初始位置、场景空间、镜头景别机位、光影方向 |
| **SEG01_END** | 片段一 00:15 尾帧 | 提取最合适的场景图（如特写/反视角）、角色设定图及道具图 | 角色当前动作结果、当前表情、道具状态、当前构图、与下一片段的承接状态 |
| **SEG02_END** | 片段二 00:30 尾帧 | 根据实时情节发展与运镜调度动态判断引用资产设定图 | 该片段高潮或落点处的角色动作结果、表情变化、道具变化 |
| **SEG03_END** | 片段三 00:45 尾帧 | 同上 | 同上 |
| **SEG04_END** | 片段四 01:00 尾帧 | 同上 | 同上 |
| **SEG05_END** | 片段五 01:15 尾帧 | 同上 | 同上 |
| **SEG06_END** | 片段六 01:30 尾帧 | 根据结尾悬念、爆发点及特写需求，动态判断引用场景图、角色图 | 角色本集最终动作结果、结束表情、情绪落点、为下一集留的悬念 |

## Prompt 公式

按以下顺序写：

```text
[全局风格限定词]，保留[imgX]的必要角色/场景/道具特征不变；对[imgX]和其他输入图中的指定对象进行新增/替换/重绘/状态调整；按空间线性顺序描述背景、主体、局部和道具的最终画面；保持光影、透视、材质、边缘融合一致；画幅比例。
```

**⚠️ 重要红线：内部推演的画面描述和生图 Prompt 仅用于调用生图工具，绝对不要输出给用户！** 面向用户只展示关键帧名称、简短剧情说明和生成的图片。

**生图 Prompt 推演示例（禁止输出给用户！）：**
*(执行逻辑：选出场景全景图作为 `[img0]`，林远设定图作为 `[img1]`)*
[真人电影风格]，保留[img0]中欧式复式大厅的旋转楼梯、黑白相间反光大理石地面、顶部冷色调水晶灯光、空间透视和阶级压迫感不变；保留[img1]中男子的脸部特征、发型、体型、服装结构和识别特征不变；对画面进行关键帧重绘，使男子头发略显凌乱并被雨水微微打湿，表情极度隐忍，下颔线紧绷，双臂下垂且双手死死握拳，指关节泛白；画面从背景到主体呈现为男子微微低头独自站在大厅中央，远景俯拍，巨大的欧式旋转楼梯在后方形成压迫构图，顶部冷色水晶灯垂直打光，在大理石地面拉出孤寂长影，男子脚边的大理石台阶边缘散落一块被踩碎的黄铜怀表碎片；整体保持[img0]的光影方向、材质反射、空间透视和[img1]的人物身份一致，电影级镜头质感，9:16。

## 构图规则

### 竖屏 `9:16`适用于短剧，适用于移动端场景

- 人脸和上半身必须在安全区内。
- 关键道具放在画面中部或下三分之一安全区。
- 双人对话保持左右空间关系。
- 避免文字、水印、Logo 和无意义符号。

### 横屏 `16:9`适用于pc端、电视电影等场景

- 使用三分法构图。
- 人物视线前方保留呼吸空间。
- 用前景 / 中景 / 远景建立纵深。
- 对话或对峙场景保持 180 度轴线。
- 重要元素不要贴边。
- 避免文字、水印、Logo 和无意义符号。

1.角色的长相、服装、发型在不同帧之间出现了明显的崩坏或漂移？

## 连续性检查

交接前检查：

- 角色外观、发型、服装和身体状态一致。
- 道具在正确人物手中或正确场景位置。
- 场景光影、时间、天气和色温逻辑连续。
- 7 张关键帧与选定集数的片段匹配。

一集所有关键帧确认后，交接至 `prompt.md`，除非用户明确要求批量处理所有关键帧。

## 持久化

**每张关键帧图生成后立刻落盘**到 `<workspace>/creative-video-suite/<project-name>/05_keyframes/episode-XX/segment-YY/<KEYFRAME_NAME>.png`（`<KEYFRAME_NAME>` 格式 `SEG01_START` / `SEG01_END` / `SEG02_END` 等，命名约定见本文件顶部）。

**关键帧图落盘走 `cmd_workspace_copy_paths`**（同 assets 阶段，从 `AGNES_OUTPUT_DIR` 复制）；落盘前自检 §7 集成清单；落盘后写 `frames.md`（该 segment 的 prompt 摘要 + 验收表，**不**含完整生图 prompt——生图 prompt 是内部推演，按 `frame.md:95` 铁律**禁止输出给用户**）。

**阶段末落盘 `05_keyframes/frames-index.md`**：全剧关键帧总索引（按 episode × segment × KEYFRAME_NAME 列）；update `project.json.current_stage = "frame"`。

跨阶段引用：prompt 阶段读关键帧图时用 file path（`<workspace>/creative-video-suite/<project-name>/05_keyframes/...`），model 端用 HTTPS URL（来自 MCP 返回的 `data[0].url`）。前后集跨段连续性引用前一集 `SEG_END` 时走同一 file path 路径。

## MCP 工具调用

**frame 阶段默认工具**：`mcp__multimedia-creator__agnes25_image_generate`（T2I）。仅 first_frame 比例与目标 `aspect_ratio` 不一致时才调 `image_edit` 转比例（**禁**用作自由编辑）。

**image_edit 唯一合法场景**：
- 上一阶段 image_generate 输出的图比例 ≠ 目标 aspect_ratio（必须先转比例）
- 局部编辑蒙版（mask_path 局部涂改）—— 仅在用户明确要"修这张图的某个区域"时使用
- 多图合成（同 frame 内拼接多张资产）—— image_edit.image_paths[] 一次传多张

**调用前 5 步硬门控**（详见 `SKILL.md` 调用前 5 步硬门控 + `references/mcp-usage-guide.md` §6）：
1. 产品图门控（涉及产品 → product-refs/ 有图或用户显式 ack）
2. 输入源 HTTPS URL（参考图全是 URL）
3. 中文 prompt（含风格锚点）
4. mode 互斥（image_generate 不传 image_paths / first_frame / images）
5. 参数 schema（size / ratio / num_images 取值合法）

**失败处理**：单次失败重试 2 次（**0 微调**，按 attempt 1 原样重试）；连续 3 次失败停下问用户。**不**降级（image_generate 失败 → 不降级 image_edit）。

> **🔗 硬编码 MCP 调用**（2026-09-08 锁定）：调 `image_generate` / `image_edit` 之前必读 `references/mcp-call-templates.md`——image_edit 转比例走 T01、多图合成走 T02、局部编辑走 T03；不得自由组合 `image_paths[]` 顺序或 prompt 结构。

## Widget emit

**emit 时机**：**追加模式**——每生成一张关键帧图后**立即** emit `frame-keyframe-grid` widget（HTML 模板 + 占位符替换见 `references/widget-templates.md` §5）。**不**等全部 7 张完成才 emit 一次。

**数据来源**：`05_keyframes/episode-XX/segment-YY/<KEYFRAME_NAME>.png` 的 HTTPS URL（来自 `image_generate` 返回的 `data[0].url`，记到 stage .md 头部映射）。

**关键帧命名约束**（widget 分组 key）：
- `SEG01_START` / `SEG01_END` / `SEG02_END` / `SEG03_END` / `SEG04_END` / `SEG05_END` / `SEG06_END`（drama 默认 7 张）
- 命名错位会破坏 widget 帧序显示

**占位符替换规则**：
- `{{episodeLabel}}` → `第1集` 等
- `{{frameCount}}` → 该集关键帧总数
- `{{segmentLabel}}` → `segment-01` 等
- `{{frameUrl}}` / `{{frameName}}` → `05_keyframes/episode-XX/segment-YY/<KEYFRAME>.png` HTTPS URL

**追加语义**：每次 emit 包含**该 segment 已生成的关键帧**（含本次新增）；按 episode × segment 二维网格展示，让用户一眼看到帧序对不对。

**Markdown fallback**：保留所有关键帧图按 segment 分组 inline。**禁**只 emit widget 不写 fallback。

**commercial 不调 frame 阶段**——Marketing 强门控禁止分镜图，UGC / Corporate 走 `storyboard-shot-table` widget 代替。

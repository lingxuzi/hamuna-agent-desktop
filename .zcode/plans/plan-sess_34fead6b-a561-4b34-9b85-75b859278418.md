## MiniAppCenter / Marketplace UI 重做

### 现状问题（先说清楚为什么要动）

这两个页面目前**用的是不存在的 CSS 变量**。全仓 10 个主题文件里没有任何一处定义 `--surface`、`--border`、`--accent-ink`、`--surface-2`——只有这两个文件在用。后果：

- `bg-[var(--surface)]` 在计算值阶段失效 → 卡片背景回退成 `transparent`，没有面板感
- `border-[var(--border)]` 回退成 `currentColor` → 边框变成满强度文字色，暗色模式下接近白色
- 错误横幅硬编码 `red-300/red-50/red-800`，不跟随主题，且被 `CLAUDE.md:225` 明令禁止

所以这次不只是"换皮"，是把两页从一套失效的样式接回真实的设计系统。

### 设计基准

`docs/V1-STYLE-GUIDE.md` + `src/renderer/pages/space/**`（这是仓库里被文档指定为权威来源的实装代码）。真实 token：

| 用途 | 替换为 |
|---|---|
| 页面底 / 卡片 / 凹陷区 | `--paper` / `--paper-elevated` / `--paper-inset` |
| 文字四级 | `--ink` / `--ink-secondary` / `--ink-muted` / `--ink-subtle` |
| 描边 | `--line` / `--line-subtle` / `--line-strong` |
| 唯一强调色 | `--accent-warm`（配 `-subtle` / `/20` 透明度写法） |
| 主/次按钮 | `--button-primary-bg` + `--button-primary-text` / `--button-secondary-*` |
| 错误 | `--error` / `--error-bg` |

页面骨架沿用 space 页的标准结构：`h-full overflow-hidden` 外层 + `SPACE_BACKGROUND_STYLE` + `PAPER_GRID_STYLE` 纸纹遮罩，顶部 `min-h-12` header 条，下面**唯一**一个 `min-h-0 overflow-y-auto` 的 `<main>`。内容框 `mx-auto max-w-6xl`。

直接复用 `spaceUi.ts` 已导出的常量（`SPACE_COLLECTION_FRAME_CLASS` 等），不新造一套。

> 注：`V1-STYLE-GUIDE.md:37` 说 Launcher hero 用 Playfair 衬线，这条**已过时**——实装 `hamuna-default.css:288` 用的是 `--font-display`（无衬线，weight 300）。本次全用无衬线，与该文档 §2「pages 内 100% sans」一致。

### MiniAppCenter

**功能介绍区（按你选的：常驻顶部，空态时展开）**

- 有安装时：一条紧凑横条 = 图标 chip + 一行说明 + 已装数量
- 无安装时：展开为 完整标题 + 说明段 + 3 张能力卡 + 虚线空态（含"去市场"CTA）

1. **独立标签页** — 每个小程序跑在自己的标签页里，与对话互不干扰

3. **沙箱内运行** — 默认纯前端 iframe；需要文件 / Git 时才声明 worker 与对应权限

（刻意不写"MiniApp 能调用宿主 AI"——`icon-generator` 虽然声明了 `ai.enabled`，但 `ui.js:6-10` 注明该 invoke 在 13→2 精简中被砍掉，目前是占位实现。）

**卡片**（重做，`miniapp-center-card-<id>` 保留）
- 整卡可点，沿用"卡片本身就是 `<button>`"的简单形态（这里没有嵌套操作，不需要 AgentCard 那套 overlay button）

- 搜索框沿用 `IssuesWorkspace.tsx:215` 的 house 形态：`h-9 rounded-xl border border-[var(--line)] pl-9 pr-10 focus:border-[var(--accent-warm)]`，左侧 `Search` 图标、右侧 `X` 清除

**详情页**重做为 house 结构：sticky header（返回 + 图标 + 名称 + 来源 pill）→ 内容框 → 说明 / 标签 / 安装路径（mono）→ 操作按钮。

### 顺手修掉的缺陷

1. **错误态与空态同时渲染** — `catch` 里 `setItems([])`，导致红横幅和"还没有安装任何小程序"一起出现。改为独立的 error 分支 + 重试按钮，**只**显示错误。
2. **Marketplace hash 路由跨标签页串台** — hash 是 window 全局的，关掉 tab 再开新的会直接落到上次看的详情。挂载时重置为列表态。
3. **详情 appId 找不到时静默退回列表**，且 URL 还留在 detail。改为同步纠正 URL。
4. **卸载没有二次确认**（只有安装有）。补 `ConfirmDialog` + `confirmVariant="danger"`。
5. `miniapp-center-grid` / `miniapp-center-kind-<id>` 等无测试引用的 testid 会清理；被测试引用的全部原样保留。

### 需要改的一处测试（有意为之）

`Marketplace.test.tsx:111-120` 靠**类名嗅探**区分弹窗确认按钮和页面安装按钮：

```ts
b.className.includes('bg-[var(--button-primary-bg)]') && b.textContent?.includes('marketplace.install')
```

它成立的前提是页面安装按钮用 `bg-[var(--accent)]`——而 `--accent` 根本不存在。**一旦按设计系统把页面主按钮改成 `--button-primary-bg`，`buttons.find()` 会先命中页面按钮，点开弹窗却永远不发出安装请求，测试挂。**

改法：把查找范围收窄到 `role="dialog"` 容器内，而不是靠类名区分。这是对脆弱测试的正确修正，不是绕过。

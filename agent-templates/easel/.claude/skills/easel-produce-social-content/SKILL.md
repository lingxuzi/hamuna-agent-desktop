# 社媒内容

跨平台的**兜底**内容生成器。多平台一次成稿、快速起草、平台不确定时的默认选择。

## 该谁干

| 场景 | 谁干 |
|---|---|
| 小红书整套笔记（多卡片 + caption + tags 全流程） | 直接在本技能里做，但按小红书的卡片规则 |
| 某条视频的分镜口播脚本 | 脚本模板还没移植，先用本技能出钩子和结构，分镜手写 |
| 落地页/详情页/信息流带货文案 | `easel-produce-copywriting` |
| 只是润色已有文字 | `easel-produce-text-polisher` |

## 输入（缺的从画像补，再缺就用通用默认）

平台 · 内容类型 · 主题 · 目标（互动/引流/品牌/获客）· 受众 · 调性 · 可用素材

## 怎么走

1. **锁平台规范** — 读 `.claude/references/platform-specs.md`，拿字数、画幅、发布时间、内容规则
2. **写钩子** — 从 `.claude/references/hook-title-formulas.md` 选**一个**公式。钩子决定 90% 的表现
3. **排结构** — 按内容类型：
   - 小红书图文 → 封面钩子 + 卡片组大纲 + 正文
   - 短视频 → 钩子 + 正文 + CTA（前 3 秒定生死）
   - 公众号/知乎长文 → 标题 + 开头 + 分段主体 + 收尾
   - 微博 → 140 字精华 + 话题
4. **加标签** — 按平台规则。小红书 5–10 个、微博 1–3 个 `#话题#`、抖音 3–5 个、B站 4–10 个
5. **字数校验** — 必做，不靠肉眼：

   ```bash
   echo "正文内容" | node scripts/wordcount.mjs count --json
   # 或
   node scripts/wordcount.mjs check --target 55 --tolerance 0 -f outputs/<主题>/x.md
   ```

   读 `social_count` 与平台上限比，超了压缩再测。

6. **去 AI 味（强制门）** — 按 `.claude/references/zh-ai-markers.md` 评五维，**≥45/50**。不过先改。
7. **出变体** — 每个平台 2–3 个版本，供 A/B 或分日发

## 每个平台交付什么

```
[钩子首行]

[正文]

[CTA]

[标签]

字数：N / 平台上限
```

外加：建议发布时间、发布后跟进动作、配图/封面方向。

## 合规

避违禁词与限流词（小红书/抖音尤其严）；话题数量合规范；外链按平台习惯放（微博正文、小红书评论区、X 第一条回复）。发布前的硬拦扫描见 `easel-publish`。

## 无画像时

问目标平台，用通用最佳实践，末尾补一句「有画像能更准」。

# 归因层

发布之后的复盘。这一层让下一个循环做得更好。

## 做什么

1. **拉数据** — 播放/阅读、点赞、收藏、评论、涨粉、完播率
2. **判表现** — 和该账号历史基线比，不是和全网热门比
3. **读评论** — 高频诉求、高频质疑、有没有人问"链接在哪"
4. **归因** — 表现好是因为选题、钩子、形式、还是发布时间？给一个主因，不要列十条可能
5. **回流** — 真正可复用的经验写进 `memory/topics/` 或 `03-USER.md` 的第六维（**先问用户**）

## 输出格式

写进 `outputs/<主题>/report.md`。对话里只给三行：表现如何、主因是什么、下次改什么。

## 边界

- 数据说话。表现差就是差，不找"算法压了"这种借口，除非有数据支持
- 不把一次性参数（某天的具体标题、某次临时配色）当经验沉淀
- 回流到画像前必须问用户

## 心跳里的轻量版

心跳巡检会调用这一层的**精简形态**，不是完整流程：

- **只做**「1. 拉数据」+「2. 判表现」+ 有明确信号才写进 `memory/topics/`
- **不做**完整 report.md、不做评论分析、不做画像回流
- 一次心跳最多沉淀一条观察，没有明确信号就什么都不写

区别在于：交互场景是用户要复盘，要产出完整报告；心跳场景是巡栏，只记录异常和亮点，供用户回来时看。完整复盘留给用户主动发起。

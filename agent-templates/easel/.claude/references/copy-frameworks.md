# 文案框架库

*选一个框架 = 一条内容主线。框架决定「信息怎么排布」，不决定「字怎么写」。**选定后只用一个，不混用。***

## PAS — 痛点 → 放大 → 方案
- **Problem** 一句话点破读者正在经历的具体困扰，越具体越有代入感
- **Agitate** 不解决会怎样（成本、尴尬、持续困扰），让人坐不住
- **Solution** 给出解法，落到可感知的结果

适用：带货、种草、卖服务、详情页 —— 任何「读者有明确痛点」的场景。

## AIDA — 注意 → 兴趣 → 欲望 → 行动
- **Attention** 钩子抓眼（痛点 / 反差 / 利益 / 提问）
- **Interest** 放大相关性，让用户觉得「说的就是我」
- **Desire** 卖点 + 证据 + 场景，制造想要
- **Action** 明确 CTA + 行动理由（限时 / 赠品 / 价格锚点）

适用：信息流广告、落地页、新品发布。

## BAB — 现状 → 改变后 → 桥梁
- **Before** 用户当前的糟糕或停滞状态
- **After** 用了之后的理想状态
- **Bridge** 从现在到理想的那座桥

适用：前后对比强烈的转变类（减肥 / 学习 / 效率）。

## FAB — 特性 → 优势 → 利益
- **Feature** 客观拥有什么（成分、参数、功能、材质）
- **Advantage** 这个特性带来什么好处（比别的强在哪）
- **Benefit** 对用户意味着什么

写法：`因为{特性}，所以{优势}，这意味着你能{利益}`。主推利益，用特性做证据。

适用：卖点提炼、详情页卖点分层。

## 4U — 有用 / 紧迫 / 独特 / 具体
用于标题或信息流首行自检，四条尽量多占。

## STAR — 情境 → 任务 → 行动 → 结果
- **Situation** 谁在什么处境
- **Task** 当时要解决的什么问题
- **Action** 一步步做了什么
- **Result** 可量化的成果

适用：案例复盘、经验分享、方法论拆解。

## SLAY — 故事 → 道理 → 建议 → 你
- **Story** 一段有画面的小故事开场
- **Lesson** 从故事里提炼一个观点
- **Advice** 给可落地的具体做法
- **You** 把话题抛回读者，引导互动

适用：个人向、观点输出、求共鸣与评论。

## 怎么选（没指定就看内容目的）

| 目的 | 框架 |
|------|------|
| 读者有明确痛点、要转化 | PAS |
| 要从围观引到心动 | AIDA |
| 前后状态对比强烈 | BAB |
| 逐条提炼卖点 / 标题自检 | FAB / 4U |
| 有案例数据、讲怎么做到的 | STAR |
| 讲故事输出观点、求共鸣 | SLAY |

判断依据是内容目的，不是平台。

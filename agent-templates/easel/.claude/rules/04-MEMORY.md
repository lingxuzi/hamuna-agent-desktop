# MEMORY.md — 长期记忆

*精选过的记忆。是提炼的精华，不是原始流水账。*

## 关于这个文件与记忆系统

- **共享语境下要注意** — 这个文件有账号的私人上下文。在群聊或共享会话里，不要泄露偏好、决策和账号细节。

### 三层记忆

**核心记忆（本文件）** — 每次会话自动加载
- 放什么：跨项目的经验、关键决策、用户偏好、账号硬规则
- 不放什么：详细的项目过程（那是项目沉淀的事）
- **每条加时间戳 `(YYYY-MM-DD)`** —— 方便追溯、判断新旧、定期清理

**项目沉淀（`memory/topics/<name>.md`）** — 做某个项目前读
- 放什么：一个项目/主题的全部积累 —— 状态、关键事实、做了什么、什么有效、什么无效、决策与理由、下一步
- 比核心记忆详细，比日志精炼
- 项目进入新阶段时更新

**日志（`memory/YYYY-MM-DD.md`）** — 会话开始时读今天 + 昨天
- 放什么：当天发生了什么，原始时间记录
- 是所有记忆的源头，但按项目检索效率低

### 信息流向

```
日志（原始素材）→ 项目沉淀（按主题综合）→ 核心记忆（跨项目精华）
```

- 干活时：只写日志
- 维护时：从日志同步到项目沉淀，提炼新经验到本文件
- **信息只存一处** —— 项目沉淀和核心记忆之间不要重复

### 什么时候读什么

- 刚醒来 → 本文件已加载 + 读今天/昨天的日志
- 准备做某个项目 → 读 `memory/topics/<name>.md`
- 记忆维护 → 读最近所有日志 + 所有活跃项目沉淀

## 经验教训

按主题归类。平铺的列表很快就会变得没法读。

### 文案

*(什么开头有效、什么结尾能带来互动、标题的长度和句式。)*

### 视觉

*(封面、构图、配色、字体的实际效果。)*

### 平台

*(各平台的推荐机制、审核口径、限流触发条件。)*

### 发布时机

*(什么时候发效果更好，什么节点要避开。)*

## 重要决策

*(关键决策和当时的理由。)*

## 用户偏好

*(用户怎么工作最顺、明确说过喜欢和讨厌什么。)*

## 账号数据

*(粉丝数、爆款记录、有效选题类型。每条带日期。)*

## 当前进行中

*(正在做的项目、待发的排期、需要跟进的反馈。)*

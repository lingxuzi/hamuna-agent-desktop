# PUBLISH-POLICY.md — 发布红线

*发布是不可逆的外部动作。这一节不是建议，是硬约束。*

## 发布模式

工作区有两种发布模式，由应用配置决定，当前模式以运行时提示为准：

| 模式 | 你被允许做的事 |
|---|---|
| **manual（默认）** | 只能产出内容 + 导出发布包。**不能调任何平台发布工具。** 调了会被 hook 直接拒绝，不走权限询问 |
| **automated** | 可以真发，但每次发布前必须拿到用户当次明确确认 |

不确定当前是哪种模式时，按 `manual` 处理 —— 生产内容永远安全，误发不可撤销。

## 硬拦（命中即停，不许发布）

对外发布的文案、标题、话题、评论、回答里出现下列任何一项，就是不合格：

- API Key、token、secret、密码
- 内部域名或内部 URL（含内网 IP、内网端口、代理地址）
- 内部绝对路径（`/Users/...`、`C:\...`、`~/.hamuna/...`）
- 执行环境变量名、调试片段、配置文件内容
- 用户真实姓名、手机号、地址、身份证号等未公开的个人信息

**常见泄露源是把报错、命令输出、配置示例顺手复制进文案。** 对外内容只保留用户真正要发布的信息。

## 提醒但不硬拦

- 提到 AI、模型名、工具名 —— 技术内容确有需要时正常用，其余场景避免自曝制作工具
- 极限词（最、第一、唯一、100%）—— 平台可能判定违规，提示但不阻断
- 医疗、功效、收益承诺 —— 提示风险，让用户自己判断

## 发布前必做的三件事

1. **人设一致性检查** — 用 `easel-publish-persona-check` 打分。80 分及以上 pass，低于 80 是 warn：把分数、关键偏离和修改建议给用户看。**人设检查只提醒，永不阻断。**
   - 评分优先比较账号定位、内容赛道、内容形式、目标受众。不能只因语气相似就给跨赛道内容高分。
2. **平台适配检查** — 各平台的标题/正文长度限制、媒体必需、仅视频约束。这些在发布前就判完，不要发到一半失败。
3. **硬拦扫描** — 上面「硬拦」那一节逐项过一遍。

## 发布动作本身

- **主战场是内置浏览器**（`hamuna browser …`）：用户看得见，登录态就是他自己那个窗口的。详见 `.claude/references/browser-routing.md`。
- **视频不能用内置浏览器上传。** 内置浏览器的文件注入上限 12 MiB，视频必然超限。抖音、视频号、B 站「仅视频」的约束意味着这三个平台的发布必须走 headless，而 headless 的登录态是独立的一份。这不是可以绕过的限制，别试。
- `automated` 模式下，每一次真实发布都要有一次用户当次确认。不是「之前说过可以」就算。
- 确认文案要写清：发到哪些平台、发什么、是不是真发（不是草稿）。
- 发布失败就报失败，不要重试到用户不知情。记录失败原因。
- 发布成功后留痕：平台、标题、画像、时间、人设评分。

## 心跳巡检场景（重要）

心跳是**无人值守**的：没有用户在旁边，但 SDK 权限是 `fullAgency`（`src/server/index.ts:9657` 刻意如此，否则工具调用会一直卡在权限询问上直到超时）。**没人会拦住你，只能自己守。**

心跳期间的额外约束，优先级高于一切任务目标：

1. **不发布。** 即使是 `automated` 模式也不行 —— 「用户当次确认」这个前提在心跳里不成立。发现该发的内容，只提醒，等用户回来。
2. **不碰浏览器。** 内置浏览器需要可见的 Chat session，心跳里开不起来；headless 能开但没有任何发布授权。**巡检只读本地数据**（`outputs/`、`memory/`、内容库），不打开任何平台页面。
3. **不登录、不扫码、不改账号。**
4. **不花钱。** 不调付费生成（图/视频/音乐/TTS）。
5. **不改画像。** `.claude/rules/` 只在用户明确要求时改。
6. **能不动手就不动手。** 没有明确信号就回 `HEARTBEAT_OK`。沉默是正确行为。

具体巡检清单在 `<workspace>/HEARTBEAT.md`，那里面也有一份独立的红线。**两处都要遵守，取更严的那个。**

## 产物与导出

`manual` 模式下你的终点是**导出发布包**：内容文件 + 元数据（标题、正文、话题、目标平台、建议发布时间）+ 每个平台的官方发布入口。用户自己拿去发。

导出也要过一遍上面的硬拦扫描。

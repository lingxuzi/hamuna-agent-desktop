自动巡检，没人在旁边。按下面的步骤走，**能不动手就不动手**。

## 1. 到点发布（先判有没有面板）

心跳是无人值守的，**浏览器面板不是** —— 面板属于一个正在屏幕上打开的 Chat 会话。
所以这一步先探一下自己在不在有面板的会话里：

```bash
hamuna browser list
```

- **能看到当前 session 的 browser 状态** → 说明有面板在。继续往下走发布。
- **返回 `No browser is open for session X`** → 说明没有面板。**不发布**，不要
  自己 `browser open`、不要去点发布按钮。发一条需要用户处理的通知，然后继续第 2 步：

  ```
  [HH:MM] ⏰ 待发布提醒
  - 《标题》原定 HH:MM 发到 平台，到点了但现在没有浏览器面板，我没法代发。
  - 处理：打开这个 agent 的 Chat，让浏览器面板在；或者你自己去平台发。
  ```

  多条到点的一次说完，不要一条一条刷屏。

**以下只在「有面板」时执行：**

1. `hamuna ops list asset --json`，自己按 `scheduledAt` 过滤出到点的（前后 30 分钟窗口）。

   > **没有 `hamuna ops due`。** `ops` 的动词只有 `list / add / update / remove`，别的
   > 词不会报错 —— 它静默兜底成「读全量台账」，你会拿到全部素材并误以为是到点清单。
   > 复数 `assets`、`stats`、`get` 同理。到点与否只能自己拿 `scheduledAt` 和当前时间比。

2. 没有 → 安静跳过。
3. 有 → 逐条处理：
   - 状态是 `ready` 才发。停在 `draft` 的报一条"到点但没就绪"，不动它。
   - 对照 `memory/YYYY-MM-DD.md`：今天已经报过"已提交 / 待最终确认 / 发布动作失败"的同一条，**这轮不再重试**，直接跳过（等用户处理，或等明天）。
   - `hamuna browser publish --platform <id> --text "发布"`。**这是唯一通道**，不要 `browser open` 发布页再手填 —— 那条路绕过审批、不留记录。
   - 发完回读创作者后台的作品列表核对；核对逻辑见 `05-OPS.md` 的「状态机」一节。真在列表里读到这一条才 `--status published`，否则 `--status unverified`。

用户明确说过"发""发布""帮我发这条"的，按当时指令走，不等心跳窗口。

## 2. 例行巡检

做一件轻量的、确定性的检查。优先级从上到下，**每轮只做一件**，做完就停：

- `hamuna ops list asset --json` 里有没有 `scheduledAt` 已过但状态还是 `ready` 的？（漏发）
- 最近 7 天有没有 `published` 但还没复盘的？提醒一句就行，不要自作主张写复盘
- 有没有 `status: draft` 且 `progress` 好几天没动过的素材？

都没有 → 这一节跳过。

## 3. 该说就说，不该说就沉默

有事才通过当前通道发一条消息。没事就回复：

```
HEARTBEAT_OK
```

## 约束

1. **不凭空打扰。** "今天还没有选题"不是紧急事件，除非已经连续好几天空转。
2. **不替用户做决定。** 发现问题可以提一句"要不要我现在复盘一下？"，不要直接开干。
3. **一次一件事。** 心跳不是工作会，不要在一次心跳里又发帖又复盘又清理台账。
4. **发布必须走浏览器。** 这一步只允许浏览器 MCP / `hamuna browser` 工具链。不写脚本、不调内部 API、不造请求；拿不到就停下报 blocker。
5. **失败就停，别改状态。** 浏览器发布动作失败（按钮点不动、页面结构变了、上传卡住）→ 把卡点写进 `memory/YYYY-MM-DD.md`，通知用户。素材留在 `ready`，下一轮再看。**不要自动重试发布动作**，等用户确认页面状态或手动处理后，再按用户指令重试。详见 `05-OPS.md` 的「发布纪律」一节。登录态掉了：只跳过这个平台，发一条提醒，**同一轮不要再碰这个平台**；其他平台该发继续发。见 `CLAUDE.md` 的红线「登录态失效只停那个平台」。
6. **发布只能用 `hamuna browser publish`。** 不要用 `browser click --text "发布"` 代替 —— `click` 走自动放行、不弹审批、不留记录，等于绕过整套发布闸。见 `05-OPS.md` 的「发布纪律」一节。

   > **素材状态只有四个值**：`draft / ready / published / unverified`。`blocked` 和
   > `making` 都不存在，`--blocked` 这个 flag 也不存在。卡点写进 `memory/`，不要
   > 硬造一个状态 —— `hamuna ops update asset --status blocked` 会被 store 拒。
7. **不重复。** 上一轮说过、这轮没新进展的事不要再提。翻 `memory/` 最近的日志确认。
8. **拿不准就沉默。** 回 `HEARTBEAT_OK` 是正确行为，不是失败。

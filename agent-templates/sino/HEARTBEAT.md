自动巡检，没人在旁边。按下面的步骤走，**能不动手就不动手**。

## 1. 到点发布（每次必做）

`hamuna ops list asset --json` 看有没有 `status: ready` 且 `scheduledAt` 已经过了的。

- 有 → 按 `ops-publish` skill 发出去，然后**回读核实**：创作者后台作品列表里找得到就置
  `published`，找不到 / 列表还没刷新就置 `unverified`。
- 登录态失效 → **只停这个平台的发布**，别的平台到点的照发。这一轮结束时把被挡住的平台报给用户（「douyin 需要你扫一次码」），别把整轮丢掉。
- 没有到点的 → 什么都不做。

**点了发布按钮不等于发成功。** 只有回读到作品列表里真有这一条才算。

## 2. 物料入库（每次必做）

`ops/inbox/` 里有新批次文件夹 → 按 `ops-intake` skill 的流程入库：建一条 `draft` 素材，
原件整批搬到 `ops/assets/imported/`。

- `ops/inbox/` 空 → 什么都不做
- `ops/assets/imported/` 里有没被任何素材引用的批次目录 → 上一轮搬完了但账本没记上，补一条素材

入库完直接接着做稿（`ops-produce`），不要入库完就停下等人发话。

## 3. 复盘回流（每次必做）

`hamuna ops list review --json` 看最近投放的复盘数据。

- 有素材已经投放超过 48 小时、但还没建复盘 → 去创作者后台把数据读回来，`hamuna ops add review` 录一次。**这个平台的登录态失效就跳过这条复盘并通报，不要用猜的数字填。**
- 已有的复盘出现新规律 → `hamuna ops add rule --source reflection`，`status: proposed`，`confidence` 按样本量给（一条样本不给超过 0.4）
- 都没变化 → 什么都不做

**不要为了"有话说"硬造结论。** 两条数据说服不了任何人。

## 3.5 评论线索（每次必做）

同一次进后台，**顺手把我们作品下面的评论读一遍**，按 `ops-review` 的「读评论 → 记线索」记成线索。

- `hamuna ops list clue --json` 看已经记了多少，避免同一条评论记两遍（`--comment-id` 是天然键，后端会合并）
- 读不到评论页 → 跳过，**不要报错**，也不要改成去读别人作品的评论区
- **只读，不回。** 评论、私信、加好友一律留给用户

**一条线索都不新增 = 这一步什么都没发生，不要说「我看了评论」。**

## 4. 排期空缺（每次必做）

`hamuna ops list asset --json` 看已排期的素材。

- 这周还有空档、手上又有 `ready` 但没排期的素材 → 按 `03-USER.md` 的 cadence 自己排一个时间，`hamuna ops update asset --id … --scheduled-at …`
- 排期撞车（同一天同一平台两条）→ 自己错开，挪到空档
- 都满 → 不做任何事

**排期自己定，但撞车和过量必须让路。** 用户没填 cadence 时才退回问一句。

## 5. 没做完的活（每次必做）

- 素材 `draft` 且 `progress` 不到 100 → **接着做完**（`ops-produce`），做完置 `ready`。
  做稿是我的活，用户不该为「稿子还没写完」这种事先花注意力。上一轮断在哪就从哪接着来
  （`progress` 和 `sourceRef` 都记着）。
- 选题停在 `planned` 超过 7 天 → 提醒「X 排进制作一周了，还做吗」
- 最多提 1 条，挑最久的

## 5.5 热点选题（每次必做）

扫一下热榜，看有没有值得蹭的热点。判据全在 `ops-topic` 里 —— 这一步只是把它的流程搬到心跳上跑一遍，**不重新发明判据**。

```bash
hamuna browser open "https://www.douyin.com/hot"   # 榜源清单见 .claude/skills/ops-topic/references/hotlist-sources.md
hamuna browser read
```

- 只扫主战平台的榜，一次最多 2 个。主战场从 `03-USER.md` 的 platforms 读；
  那儿还没填就扫台账里有方向 / 对标的平台（`hamuna ops list direction --json` / `list benchmark --json`）
- 榜读不出来（浏览器面板不可用 / 登录态失效）→ **跳过这一步**，不报错、不重试。
  降级到 `browser search` 是交互式选题的做法，心跳里不做 —— 搜出来的东西精度不够，容易提一条凑数的
- 扫到的条目按 `ops-topic` 的四道硬门 + 七维打分走一遍，**综合分 ≥ 70 才继续**
- ≥70 分的候选再往下走之前，先判断**当前档位**（读创作者后台的粉丝数，命令见 `ops-direction`）：
  **0-500 档跳过这一步** —— 那一档要发的是「统一一个方向的 10 条测试」，插一条热点就把变量换掉了
- 一次最多提 **1 条**（交互式选题最多 3 条，心跳没人盯着，门槛要更高）
- 落库字段照 `ops-topic` 的规则填，**`--note` 必须带阶段 / 热度等级 / 关联度 / 风险判断四样**

**心跳默认 4 小时一轮**（默认间隔 240 分钟，活跃时段 09:00–21:00），所以扫到的热点基本已经在**高峰期**或**衰退期**：

- 高峰期（4-24 小时）→ 拼差异化，这是心跳够得着的窗口
- 衰退期（1-3 天）→ 必须换角度（做总结 / 反思），别复述发生了什么
- 爆发期（0-4 小时）→ **这轮心跳抓不到**。想抢就把心跳间隔调到 60 分钟以内

**一条都没提 = 这一步什么都没发生，不要说「我扫了热榜」。** 跟第 3.5 步一个规矩。

## 6. 有东西要说才说

- **什么都不用做** → 只回 `HEARTBEAT_OK`，一个字都别多
- **有东西要说** → 挑最重要的**一件**说，3 行内，别罗列全部发现

一次心跳最多说一件事。用户不是来读日报的。

**排序：已经发生的事 > 还没发生的提案。** 发布结果、复盘缺口、卡住的排期这些先说；
第 5.5 步提的热点选题是**提案**（还在 `idea`），前面有更该说的就别说它。

## 红线（override 一切）

1. **先查登录态，失效只停那个平台。** 需要登录态的动作（发布、回读数据）之前先确认那个平台还是登录着的。失效 → **那个平台的这一步跳过**，别的平台、别的步骤照跑；这一轮结束时把被挡住的平台告诉用户（「douyin 需要你扫一次码」）。**不要在没有登录态的情况下重试，不要尝试自己登进去，也不要用猜的数字替它补上。**
2. **不改账号设置、不评论、不私信。** 心跳期间权限是全开的，靠你自己守。
3. **不在人没定的形态上花钱。** 付费生成（视频平台）只在选题的 `form` 说了要调的那一档才调（`video_aigc`）—— 那是人在面板上点的，我不能自己挑、自己改。`form` / `formAspect` 是空的、或者那个工具没启用，就**停下问**，别自己开工具、别自己填 key。图像 / TTS 用用户已经启用的工具——启用了就是授权，没启用就是没有。
4. **不改 `ops/state.json`。** 一切写操作走 `hamuna ops`，见 `.claude/rules/05-OPS.md`。同理：`ops/inbox/` 里人刚丢进来的文件不许改，只许整批搬走。
5. **提交过的素材不许重发。** 状态是 `unverified` 的，只能去回读核实，不能退回 `ready` 再发一次。见 `05-OPS.md`。
6. **发布只能用 `hamuna browser publish`。** 不要用 `browser click --text "发布"` 代替 —— `click` 走自动放行、不弹审批、不留记录，等于绕过整套发布闸。见 `05-OPS.md`。
7. **不重复。** 上一轮说过、这轮没新进展的事不要再提。翻 `memory/` 最近的日志确认。
8. **拿不准就沉默。** 回 `HEARTBEAT_OK` 是正确行为，不是失败。

自动巡检，没人在旁边。按下面六步走，**能不动手就不动手**。

## 1. 到点发布（每次必做）

`hamuna ops list asset --json` 看有没有 `status: ready` 且 `scheduledAt` 已经过了的。

- 有 → 按 `ops-publish` skill 发出去，然后**回读核实**：创作者后台作品列表里找得到就置
  `published`，找不到 / 列表还没刷新就置 `unverified`。
- 登录态失效 → 停下来，只报这一件（「douyin 需要你扫一次码」），这一轮其余步骤都不做。
- 没有到点的 → 什么都不做。

**点了发布按钮不等于发成功。** 只有回读到作品列表里真有这一条才算。

## 2. 物料入库（每次必做）

`ops/inbox/` 里有新批次文件夹 → 按 `ops-intake` skill 的流程入库：建一条 `draft` 素材，
原件整批搬到 `ops/assets/imported/`。

- `ops/inbox/` 空 → 什么都不做
- `ops/assets/imported/` 里有没被任何素材引用的批次目录 → 上一轮搬完了但账本没记上，补一条素材

入库完直接接着做稿（`ops-produce`），不要入库完就停下等人发话。

## 3. 复盘回流（每次必做）

`hamuna ops list review --json` 看最近投放的复盘数据。

- 有素材已经投放超过 48 小时、但还没建复盘 → 去创作者后台把数据读回来，`hamuna ops add review` 录一次。**登录态失效就跳过这一步并通报，不要用猜的数字填。**
- 已有的复盘出现新规律 → `hamuna ops add rule --source reflection`，`status: proposed`，`confidence` 按样本量给（一条样本不给超过 0.4）
- 都没变化 → 什么都不做

**不要为了"有话说"硬造结论。** 两条数据说服不了任何人。

## 3.5 评论线索（每次必做）

同一次进后台，**顺手把我们作品下面的评论读一遍**，按 `ops-review` 的「读评论 → 记线索」记成线索。

- `hamuna ops list clue --json` 看已经记了多少，避免同一条评论记两遍（`--comment-id` 是天然键，后端会合并）
- 读不到评论页 → 跳过，**不要报错**，也不要改成去读别人作品的评论区
- **只读，不回。** 评论、私信、加好友一律留给用户

**一条线索都不新增 = 这一步什么都没发生，不要说「我看了评论」。**

## 4. 排期空缺（每次必做）

`hamuna ops list asset --json` 看已排期的素材。

- 这周还有空档、手上又有 `ready` 但没排期的素材 → 按 `03-USER.md` 的 cadence 自己排一个时间，`hamuna ops update asset --id … --scheduled-at …`
- 排期撞车（同一天同一平台两条）→ 自己错开，挪到空档
- 都满 → 不做任何事

**排期自己定，但撞车和过量必须让路。** 用户没填 cadence 时才退回问一句。

## 5. 没做完的活（每次必做）

- 素材 `draft` 且 `progress` 不到 100 → **接着做完**（`ops-produce`），做完置 `ready`。
  做稿是我的活，用户不该为「稿子还没写完」这种事先花注意力。上一轮断在哪就从哪接着来
  （`progress` 和 `sourceRef` 都记着）。
- 选题停在 `planned` 超过 7 天 → 提醒「X 排进制作一周了，还做吗」
- 最多提 1 条，挑最久的

## 6. 有东西要说才说

- **什么都不用做** → 只回 `HEARTBEAT_OK`，一个字都别多
- **有东西要说** → 挑最重要的**一件**说，3 行内，别罗列全部发现

一次心跳最多说一件事。用户不是来读日报的。

## 红线（override 一切）

1. **先查登录态，失效就停。** 需要登录态的动作（发布、回读数据）之前先确认那个平台还是登录着的。失效 → 停下来告诉用户「douyin 需要你扫一次码」，然后这一轮什么都不做。**不要在没有登录态的情况下重试，也不要尝试自己登进去。**
2. **不改账号设置、不评论、不私信。** 心跳期间权限是全开的，靠你自己守。
3. **不花钱。** 不调付费生成（图 / 视频 / 音乐 / TTS）。
4. **不改 `ops/state.json`。** 一切写操作走 `hamuna ops`，见 `.claude/rules/05-OPS.md`。同理：`ops/inbox/` 里人刚丢进来的文件不许改，只许整批搬走。
5. **提交过的素材不许重发。** 状态是 `unverified` 的，只能去回读核实，不能退回 `ready` 再发一次。见 `05-OPS.md`。
6. **发布只能用 `hamuna browser publish`。** 不要用 `browser click --text "发布"` 代替 —— `click` 走自动放行、不弹审批、不留记录，等于绕过整套发布闸。见 `05-OPS.md`。
7. **不重复。** 上一轮说过、这轮没新进展的事不要再提。翻 `memory/` 最近的日志确认。
8. **拿不准就沉默。** 回 `HEARTBEAT_OK` 是正确行为，不是失败。

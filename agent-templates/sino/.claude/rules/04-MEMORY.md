# MEMORY.md — 长期记忆

*提炼过的结论，不是流水账。*

## 记忆系统

### 三层

**核心记忆（本文件）** — 每次会话自动加载
- 放：跨项目的规律、关键决定、用户偏好、一句话项目摘要
- 不放：单个选题的细节（那是 `ops/` 和 topic 文件的事）
- 每条带日期 `(YYYY-MM-DD)`

**主题记忆（`memory/topics/<name>.md`）** — 动某个项目之前读
- 放：一个系列 / 一个栏目的全部积累——做过什么、什么有效、什么翻车了、为什么
- 比核心记忆细，比日志有结论

**日志（`memory/YYYY-MM-DD.md`）** — 会话开始读今天 + 昨天
- 放：那天发生了什么，按时间流水
- 是所有记忆的原料，但按项目检索很费劲

### 信息流向

```
日志（原料） → 主题文件（按项目合成） → 核心记忆（跨项目本质）
```

- 做事时只管写日志
- 维护时把日志同步进主题文件，新的跨项目规律提上来到本文件
- **同一件事只存在一处**，别在主题文件和本文件里各写一遍

### 台账 vs 记忆

两者不重复，职责不同：

| | 台账 `ops/state.json` | 记忆 `memory/` |
|---|---|---|
| 是什么 | 现在手上有哪些活、做到哪了 | 为什么这么做、学到什么 |
| 谁读 | App 的运营面板、我 | 只有我 |
| 形态 | 结构化，可查询 | 散文，可读 |
| 写 | **只能走 `hamuna ops`** | 直接写文件 |

一条选题的**状态**在台账里；同一选题**为什么砍了**在日志里。

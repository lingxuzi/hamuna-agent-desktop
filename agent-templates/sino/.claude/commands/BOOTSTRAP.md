# BOOTSTRAP — 冷启动

第一次在这个工作区开工，或者方向要重定。**按顺序走完四步**，每一步都落进台账 / 规则文件，
不留在对话里。

不要一上来就问一串问题。先问一句最关键的，其余从已有的东西里读：

```bash
hamuna ops list --json        # 台账现在是空的还是有货
```

台账空 + `03-USER.md` 没填 → 这是全新号，走下面四步。
台账有货 → 别重跑冷启动，直接告诉用户现在手上有什么，问他要往哪走。

---

## 第 1 步 · 填账号画像

`.claude/rules/03-USER.md` 有六个维度（identity / style / audience / platforms / redlines / cadence）。
**一次只问一两项**，问完就写回去，别攒到最后一次性填 —— 一次问六条用户会随便答。

最少要拿到：

1. **账号名 + 赛道 + 一句话定位**（identity）
2. **说给谁听**（audience）—— 具体到「谁在什么场景下会看」
3. **主战场平台**（platforms）
4. **更新节奏**（cadence）—— 用户没定就先按一周 3 条走，做起来再调

**`03-USER.md` 归用户维护，但冷启动时它多半是空的 —— 空的就该由这次对话填。** 填完写回文件。

## 第 2 步 · 立方向

每个平台一条。走 `ops-direction` skill 的「冷启动：把模糊原话拆开」。

关键：**一次落齐五个字段**（定位 / 受众 / 支柱 / 目标 / 节奏），不要分批。
半张方向比没有方向更糟 —— 选题会读到一个残缺的定位。

```bash
hamuna ops update direction --platform douyin \
  --positioning "…" --audience "…" --pillar … --pillar … \
  --goal "…" --cadence "…"
```

## 第 3 步 · 定对标账号

走 `ops-benchmark` skill。方向定了才找对标 —— 「方向相近」是相对于方向说的。

找 2–3 个，给用户**看候选 + 一句为什么像**，用户点头后才落库：

```bash
hamuna ops add benchmark --platform douyin --name "…" --profile-url "…" \
  --why "…" --evidence "…" --source agent
```

**不要跳过这一步。** 没有对标账号，第一轮选题会退化成凭空想 —— 这正是「对标账号的公开内容」
这个输入源悬空的后果。

## 第 4 步 · 开第一轮选题

走 `ops-topic`。现在有了方向（判断标准）、对标账号（输入源）、画像（相关性和语气），
选题不再靠即兴发挥。

提 **1–3 条**，每条说清角度和「为什么值得做」。提完问用户挑哪条，再进 `ops-produce`。

---

## 收尾

跟用户说一句现在的状态，一句就够：

「画像填完了，douyin 方向定了：<一句话>，对标了 <N> 个号。第一轮提了 <M> 条选题，等你挑。」

不要复述填过的每个字段。

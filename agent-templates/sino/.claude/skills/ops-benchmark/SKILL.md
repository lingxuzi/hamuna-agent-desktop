# ops-benchmark — 对标账号

对标账号是**方向的参照系**，不是「我关注了谁」的收藏夹。

为什么它得单独一个 skill：`ops-topic` 的输入源表里写着「对标账号的公开内容 → `source: benchmark`」，
但台账里空着这个集合的时候，那句话是悬空的 —— 我不知道该对标谁，选题就退化成即兴发挥。
**冷启动时这一格是空的，所以它必须能被显式地建出来。**

## 开工前先读

```bash
hamuna ops list benchmark --json   # 已经有哪些对标，别重复提
hamuna ops list direction --json   # 方向在哪（对标必须方向相近）
```

再读 `03-USER.md` 的 identity / audience 两节 —— **「方向相近」是相对于这个号的定位说的，
不是「这个赛道里最大的是谁」**。找一个十万粉但受众完全不同的号当对标，等于没对标。

## 两种来源，两种授权

| 来源 | `source` | 要不要人点头 |
|---|---|---|
| 用户直接给的（「你就对标 @露营老张」） | `user` | **不用** —— 用户的话本身就是授权 |
| 我找的候选 | `agent` | **要** —— 方向是策略，对标是策略的参照系，我自选自写等于没人拍板 |

用户点头 = 他明确说「这几个可以」。没点头的候选**只留在对话里**，不进台账。

## 冷启动：找候选

冷启动（方向刚定、台账还是空的）时按这四步：

1. **拆方向** —— 从 `03-USER.md` + 方向记录里读出：品类、人群、内容支柱、语气。
2. **找候选**（两条路，先走第一条）——
   - 平台对标榜入口：`hamuna platforms <id> --json` 里的 `benchmarkEntry`。
     **它不一定是个 URL** —— 有的平台没有独立的榜页，这一格填的是「打开哪 + 点哪里」。
     这一格有值 = 已核实，照着走，别再从 `creatorHomeUrl` 重新摸索；
     **没值**（缺 = 未核实）才从 `creatorHomeUrl` 出发，用 `hamuna browser open <URL>`
     + `hamuna browser read` 现场找入口，找到把实际路径记进 `memory/topics/<平台>.md`，
     下次直接用。
     抖音那一格是「搜索页 →「筛选」面板 →「对标账号」」这种形状（榜单要登录态才给看）；
     **具体地址以 `benchmarkEntry` 里写的为准** —— 抖音换壳频繁，skill 里抄的地址会过期。
   - 公开搜索：「<品类> + <人群> 攻略 小红书」「<支柱关键词> 博主」这类。
     搜到的是**主页链接**，不是内容。
3. **读主页，只读公开页** —— `hamuna browser open <主页URL>` → `hamuna browser read`。
   看三样：这个人做什么品类、人群像不像、更新频率。这三样对得上才算候选。
   抖音看**作者主页的作品流**（`/aweme/post/`，本机实测）—— 它严格按发布时间倒序；
   搜索结果页的「最新」可能隔几周，拿它当对方的近期节奏会算错。
4. **给理由** —— 每个候选一句话说清「跟我们在哪一点上像」。说不清就是不对标。

一次给 **2–3 个**，多了等于没对标。附上主页链接让人能自己去看。

**为什么不给「像不像我们」的分数**：分数要一套稳定口径，而现在只有「读完公开页之后的判断 + 一句理由」。
理由当场能被人驳回，分数过期后没人知道它按什么口径算的。

## 落库

```bash
hamuna ops add benchmark \
  --platform xiaohongshu \
  --name "露营老张" \
  --profile-url "https://www.xiaohongshu.com/user/profile/lzycamp" \
  --why "同样做入门露营装备实测，受众重合在「刚买第一套」" \
  --evidence "2026-11-16 公开页读到 38.2w 粉，主页简介写「露营装备实测」" \
  --source agent
```

字段规则：

- `--profile-url` **必填**，而且是天然键的一半（`(platform, profileUrl)`）。少了它下次认不回来，
  同一个号会被记成两条。
- `--why` 写**定位上的相似点**，不是「内容好」。「内容好」是对所有账号都成立的话，不是理由。
- `--evidence` 写**核实到的事实 + 时间**（「2026-11-16 公开页读到 38.2w 粉」）。
  **不要单开一个粉丝数字字段** —— 那个数字会过期，过期后它就变成一句谎。
- `--source agent` 的记录是**用户点头之后**才写的。没点头就别写。
- `--source user` 的记录直接写。

## 日常维护

```bash
hamuna ops update benchmark --platform xiaohongshu --profile-url "<主页URL>" --why "新的理由"
hamuna ops remove benchmark --platform xiaohongshu --profile-url "<主页URL>"
```

- 换对标 = 先 remove 再 add（天然键变了就是新的一条）。
- 用户不满意某个对标 → 直接删，不要留着自己绕。
- 证据过期了（半年后）→ 更新 `--evidence`，别让它看起来还新鲜。

## 采集边界

**能读**：

- 公开主页（任何人的公开页）
- 平台公开的达人榜 / 对标榜（**用登录态进这些榜页是可以的** —— 榜是平台给所有人看的，只是要登录才给看）
- 用户贴过来的链接

**不能读**：

- 别人账号的后台 / 私域数据 / 私信

**永远不做**：回评论、私信、加好友、改账号设置、给别的号点赞关注。

对着别人的号「打招呼」是人在做的事，不是运营动作（见 `02-SOUL.md` 的边界）。

## 交接

落库后一句话说清：**对标了谁、像在哪一点**。不要复述字段。

「定了两个对标：露营老张（也是入门装备实测，受众重合在刚买第一套）、小李露营（更偏场景，
更新频率跟我们一样一周 3 条）。以后选题先读这两个。」

## 不要做

- **不直接编辑 `ops/state.json`。** 一切写操作走 `hamuna ops`（见 `05-OPS.md`）。
- 不自己造 `id`。后端生成。
- **不在用户点头之前把候选写进台账。**
- 不对标「这个赛道最大的号」 —— 对标要方向相近，规模大是顺带的。

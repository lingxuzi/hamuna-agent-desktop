# ops-benchmark-analysis — 拆对标账号

对标账号是参照系，拆解是把参照系变成**能拿来做判断的结论**。

`ops-benchmark` 解决「对标谁」，这个 skill 解决「他到底怎么做的、我们能抄哪一条」。
拆过和没拆过的对标账号，在选题那一段完全不是一回事 —— 没拆的只能读主页说个「他主要做 XX」，
拆过的能说出「他的爆款集中在对比类选题，占近 30 天作品的 1/4」。

**它不是第五段。** 四段循环还是那四段。这个 skill 是 `ops-topic` 的输入准备。

## 什么时候跑

- 台账里有 benchmark，但**还没拆过**（`ops list rule` 里没有 `对标@<账号名>` 开头的）→ 拆
- 上次拆的结论**过期了**（那条 rule 的 `freshness` 是 `stale`）→ 重拆，**更新那一条**，不要新开一条
- 用户点名要拆某个对标 → 拆
- **要起号了**（方向定了、还没发过几条）→ 拆一次。起号方案要拿「他靠什么涨粉」当依据，
  没拆过就没有依据，`ops-direction` 只能凭空给一个节奏

**不要每次巡检都拆。** 拆解要登录态 + 浏览器，是重活。结论有 30 天保鲜期，期内直接用。

## 开工前先读

```bash
hamuna ops list benchmark --json   # 拆谁
hamuna ops list rule --json        # 有没有拆过（找 `对标@` 开头的）
hamuna ops list direction --json   # 我们的方向 —— 差异化的对照面
```

再读 `.claude/rules/05-OPS.md` 的数字口径（`confidence` / `sampledCount` / `sampledAt` / `evidence` / `gap`）。

## 怎么读一个对标账号

取数层见 `references/data-collection.md`。一句话：`hamuna browser open <主页URL>` → `hamuna browser read`，
只读公开页。登录态可以用，但只读不互动。

抖音看**作者主页的作品流**（`/aweme/post/`）—— 严格按发布时间倒序，搜索结果页的「最新」可能隔几周。

## 拆什么

**主线只有一个：他靠什么涨粉。** 别的维度都是这条主线的证据。

一个号有粉，不是因为「他内容做得好」，是因为**有一条通路把人带走了** ——
单篇爆款拉新、稳定输出滚雪球、系列养粉、转发扩散。找出那条通路，才知道哪部分
能抄、哪部分抄了也没用（他的粉丝不投他这类内容）。

判据在 `references/viral-patterns.md`，填表在 `references/analysis-templates.md`，
量化对照在 `references/benchmarks.md`（多快算快、哪些数在公开页上算得出来）。

| 主线问题 | 靠什么回答 |
|---|---|
| **他靠什么涨粉？** | 爆款拉新还是稳定输出。看爆款篇数占比、篇均互动在涨还是在跌、互动是不是集中在少数几条 |
| **什么内容会爆？** | 爆款集中在哪类选题、哪种封面、哪种开头钩子 |
| **爆的量级够不够爆？** | 相对该号近期中位数的 3–5 倍；跟平台基准对的时候看 `benchmarks.md` |

然后才是这七项证据 —— 它们合起来回答上面三个问题，缺一项结论就站不住：

| 维度 | 要回答的问题 |
|---|---|
| 选题分布 | 他主要做哪几类？各占多少？哪类是常青、哪类是蹭热点 |
| 格式与节奏 | 主力格式是什么？多久发一次？固定时段吗？有系列栏目吗 |
| 爆款规律 | 什么内容会爆？爆款集中在哪类选题、哪种封面、哪种钩子 |
| 互动结构 | 赞评藏转什么比例？收藏型（工具向）还是转发型（情绪向） |
| 涨粉引擎 | 靠单篇爆款拉新，还是靠稳定输出滚雪球 |
| 风格人设 | 专业严肃 / 亲和真实 / 搞笑玩梗 / 文艺？封面有没有视觉锤 |
| 差异化机会 | 格式、人群、平台、人设四个维度上，他没做或做得弱的在哪 |

**「什么内容会爆」用相对倍数判**：互动量 ≥ 该号近期中位数的 3–5 倍。
拿不到精确互动数就别用这个判据 —— 降级到互动率排序，并在结论里标清口径。

**别拿大号的数对全体平均。** 小体量账号互动率天然更高（见 `benchmarks.md`），
拆一个 10w 粉的号时拿他的互动率去对平台平均，天生吃亏。

**评论区不读。** 别人作品下面的评论是别人的数据。只用互动**数**的结构，不看评论**文字**。

**「选题空白」不做。** 「竞品没做但受众有需求」要赛道整体供需数据才能下结论，
那是蓝海选题的活，不在这里下判断。

## 最近爆款清单（拆解时顺手产出）

「规律」回答「他靠什么涨粉」，「清单」回答「他最近哪几条真的爆了」。选题两样都要：
规律告诉你往哪个方向做，清单给你具体的钩子、封面、开头去改。

**只在拆解那一轮产出，不单独跑一趟。** 拆解本来就在读近 10–20 篇作品流，从中挑爆款条目
是顺手的事；为此再开一轮登录态 + 浏览器是白花时间。

- 判据就是 `viral-patterns.md` 第一节的**相对倍数**：互动量 ≥ 该号近期中位数的 3–5 倍。
  拿不到精确互动数（UI 只有约数）就**不产清单**，只产规律，并在 `--gap` 里写
  「无精确值，未出爆款清单」——约数除以约数算出来的「3 倍」是假的。
- **最多 3 条**。爆款清单不是作品列表；挑多了等于把「他发了什么」整个搬过来。
- 每条落一条 `topic`，`--source benchmark`，**`--ref` 用这条作品的链接**（不是主页）。
  这是和下面「写 topic」那节的分工：那一节写的是「他这一类选题」，`--ref` 是主页；
  这里写的是「他这一条作品」，`--ref` 是作品页。
- `--note` 写**可借的具体物**：「开头 3 秒直接上失败镜头」「封面大字报：三件只带两件」。
  写「这条很火」等于没写。
- `--hotness` 填这条的播放量（读得到才填，读不到不传）。热榜热度值不填。

爆款清单跟着拆解一起过期：`--sampledAt` 写这一轮读的时刻，30 天后当历史看。
**一条 3 天前爆的作品今天还是那条作品** —— 清单里的条目本身不会变性质，变的是
「他还在这条赛道上吗」。后者归规律管。

## 结论落到哪

三个落点，都用现有台账，不新造结构。

| 拆出什么 | 落到哪 |
|---|---|
| **他靠什么涨粉**（爆款拉新 / 稳定输出 / 系列养粉）、爆款选题类型、封面模板、开头钩子、互动结构 | `hamuna ops add rule --source benchmark` |
| 具体能做的选题（他做过、我们没做、且值得做） | `hamuna ops add topic --source benchmark` |
| **最近爆款清单**（这一轮里真的爆了的那几条作品） | 同上，`ops add topic --source benchmark`，`--ref` 用作品链接 |
| 我们自己的起号方案（目标 / 节奏 / 支柱 / 前 10 条测试发什么） | 走 `ops-direction` —— **要人点头** |

### 写 rule

```bash
hamuna ops add rule \
  --name "对标@露营老张 靠装备对比爆款拉新" \
  --rule "他的 4 篇爆款里 3 篇是两款装备的对比实测，占近 30 天作品的 1/4；篇均互动靠这几条拉起来，其余 8 条基本不动 —— 爆款拉新型，不是稳定输出型" \
  --source benchmark \
  --status proposed \
  --basis inference \
  --confidence 0.6 \
  --sampledCount 12 \
  --sampledAt "2026-11-20T15:00:00+08:00" \
  --evidence "2026-11-20 读 https://www.douyin.com/user/xxx 主页 12 篇，爆款 4 篇（来源：主页直取，XHR 精确值）" \
  --gap "只读了最近 12 篇，没覆盖 3 个月"
```

硬要求：

- **`--source benchmark`** —— 这条规律是拆**别人**的号得来的。台账里它跟「我们自己复盘出的规律」
  是两回事：它描述的是对手在做什么，不是我们该照抄的。选题时它只能当**线索**，
  我们自己的复盘验证过、`status` 转 `active` 之后，才配当筛选条件。
- **`--status proposed`** —— 竞品规律默认就是提议。凭什么转 `active`？见 `ops-review`。
- **`--name` 以 `对标@<账号名>` 开头** —— 下次重拆时靠它认出「这条是拆这个号得的」，
  然后 **update 那一条**，不新开一条。台账里躺着两份说法相反的结论，比一条旧的更坏。
- **`--rule` 要写得出「靠什么涨粉」** —— 「他主要做装备对比」是描述，
  「爆款拉新型：4 篇爆款里 3 篇是装备对比，篇均互动靠这几条拉起来」才是结论。
  `ops-direction` 要靠这条规则定起号方案，描述它用不上。
- **`--confidence` 按样本量给** —— 1 条样本 ≤ 0.3，2–3 条 0.5 左右，多次复现才给 0.7 以上。
  别硬写 0.9。
- **`--sampledCount` 是样本量** —— 看了多少**篇作品**。不是读了多少条评论（评论不读）。
  不写样本量，那个 0.6 是自说自话。
- **`--sampledAt` 写这一轮读数据的时刻** —— 保鲜期的起点。
- **规模（粉丝量级这类会过期的数字）写进 `--evidence`，不单开字段**，时间也写在证据里。
- **`--gap` 写这轮还欠什么** —— 「只读了 12 篇」「没拿到精确互动数」「评论区没看（不采）」。
  没看到的东西写进缺口，别猜数字填。

### 写 topic

```bash
hamuna ops add topic \
  --title "两款露营椅对比：哪把能塞进后备箱" \
  --platform douyin \
  --source benchmark \
  --ref "https://www.douyin.com/user/xxx" \
  --note "对标@露营老张 的爆款选题类型，他的对比类篇均互动是其它类型的 3 倍"
```

`--ref` 必须是**主页链接**，`--note` 说清是哪个对标的什么给了启发 ——
「参考了对标账号」等于没说，下一轮没人知道该去看谁。

### 交出起号方案

拆完别自己写方案。**方案是方向，方向要人点头。**

这一段交给 `ops-direction`：它读 `ops list rule --json` 里 `source: benchmark` 的规则
（就是上面那条「他靠什么涨粉」），配上我们的定位和所处阶段，落成 goal / cadence / pillars。

交接时把这三样说清楚，`ops-direction` 才接得上：

1. **他靠什么涨粉** —— 单篇爆款拉新 / 稳定输出滚雪球 / 系列养粉，一句话。
2. **我们能借的那一条** —— 只有一条。七维全搬过去等于没拆。
3. **这条结论的样本量和采样时刻** —— 规则里的 `sampledCount` / `sampledAt`，
   它们决定这条结论还有多少天新鲜（30 天）。

同理，拆出「我们其实应该往 X 方向走」这类结论时，**不要自己改方向** ——
走 `ops-direction` 的修订流程，要人点头。

## 红线

- **只读，不互动**：回评论、私信、加好友、点赞关注 —— 一律留给用户。
- **不读别人作品下面的评论区**。互动**数**能读，评论里的**文字**不读。
- **不碰别人账号后台 / 私域数据**。公开主页、公开达人榜、用户贴的链接可以读。
- **规模写证据，不写字段**。粉丝量级这类数字会过期，过期后就是一句谎。
- **拿数据说话**。没数据就写进 `--gap`，别把推断写成结论。

## 不要做

- **不替 `ops-benchmark` 找对标** —— 找谁、落库、点头是那个 skill 的事。这里只拆已经落库的。
- **不替 `ops-topic` 选题** —— 这里只提供依据。七维打分是那一段的事。
- **不拆自己的号** —— 拆自己看 `ops-review`（那边有现成的口径和复现逻辑）。
- **不出报告文件**。结论落台账就够了，别再写一份 markdown 躺在那没人读。

## 交接

一句话说清**拆出了什么可用的结论**，不逐条复述字段：

「拆了@露营老张：他是爆款拉新型 —— 4 篇爆款里 3 篇是装备对比，占近 30 天作品的 1/4，
其余篇目不动。封面是大字报比实拍高一倍互动，他周更 3 条固定周三晚上。
已落成 1 条规则、2 条选题。要不要照着这个打法起号，你点一下 —— 我把方案提给方向那一段。」

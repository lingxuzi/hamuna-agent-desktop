## 本项目的取数层

台账里的对标账号一律用内嵌浏览器读：

```bash
hamuna browser open <主页URL>   # 打开的是 App 内嵌 webview，用户看得见，过程透明
hamuna browser read              # 把当前页读成 markdown
```

- **登录态可以用**：公开主页、平台公开的达人榜 / 对标榜页。榜是平台给所有人看的，只是要登录才给看。
- **只读，不互动**：回评论、私信、加好友、点赞关注，一律留给用户。
- **打不开就退一级**（见下面的降级链），别反复重试。

### 统计数字：UI 上的是约数，精确值要走 XHR

- 抖音的 `digg_count / comment_count / collect_count / share_count` **只有 XHR 拦得到精确值**；
  网页 UI 上是约数，收藏数 UI 干脆不显示精确值。要做「爆款判定」「互动结构」就得拿精确值。
- 抖音详情页的 API 直连要签名，裸请求会被拒 —— 一律「导航 + XHR 拦截」，不要改回直连。
- **拿不到精确值就别用倍数判爆款**（见 `viral-patterns.md` 第一节）—— 约数除以约数算出来的
  「3 倍」是假的。这种情况降级到「互动率排序」，并在结论里标清口径。

### 抖音的作品流

- **作者主页 `/aweme/post/`** 严格按发布时间倒序 —— 这是「对方最近的节奏」的唯一准入口。
- 搜索结果页的「最新」可能隔好几周，拿它当更新频率会算错。
- 平台内的对标账号入口见 `hamuna platforms douyin --json` 的 `benchmarkEntry`。

## 能采到什么 vs 采不到什么

| 数据 | 来源 | 可得性 |
|------|------|--------|
| 账号昵称 / 简介 / 定位标签 | 主页 | ✅ 公开 |
| 粉丝量级 / 获赞与收藏总量 | 主页 | ✅ 公开（多为量级，非精确值） |
| 作品列表 / 标题 / 封面 / 发布时间 | 主页信息流 | ✅ 公开 |
| 单篇点赞 / 收藏 / 评论数 | 内容页 | ✅ 公开（部分平台需登录态，外部常缺失） |
| 评论区内容 / 高赞评论 | 内容页 | ⚠️ 部分可得，翻页常受限 —— **本项目不读，见红线** |
| 播放量 / 完播率 / 粉丝增量 / 转化 | 创作者中心 | ❌ 外部不可得，**不要编造** |

**原则**：拿不到的数据如实标注"无公开数据"，用可观测的替代指标（如点赞/收藏比、评论**数**）推断，绝不虚构精确数字。

> **本项目的裁剪**：「评论区内容 / 高赞评论」这一行本项目**不采** —— 别人作品下面的评论是别人的数据，
> 我们要的是观众对**我们自己**内容的反应。互动**数**（赞/评/藏/转的比例）能读，评论里的**文字**不读。

## 采集顺序（逐级降级）

1. **主页直取** — `hamuna browser open <主页URL>` + `hamuna browser read`，提取简介、粉丝量级、
   近期作品标题与互动量级。
2. **平台内搜索补全** — 主页读不出来时（空内容 / 登录墙 / 风控页）：
   - 抖音：搜索页 →「筛选」面板→「达人」或「对标账号」，再从结果进作者主页。
   - 其它平台：平台内搜索账号名，或 web 搜索 `{账号昵称} {平台}`、`site:<平台域名> {账号昵称}`、
     `{账号昵称} 爆款`、`{账号昵称} 数据 / 粉丝` —— 从第三方公开报道取量级。
3. **样本抽取** — 拉不全量作品时，抽近期 10–20 篇代表内容手动归类，标注"基于样本，非全量统计"。
4. **热点交叉** — 借势分析走平台公开热榜：`hamuna browser open <热榜URL>` → `hamuna browser read`。
   抖音热榜是页面内 fetch 出来的，`browser read` 能读到。

## 各平台在本项目里的读法与降级

| 平台 | 本项目怎么读 | 读不到就退到 |
|------|-------------|-------------|
| 抖音 | 作者主页 `/aweme/post/` + XHR 拦截拿精确统计 | 搜索页筛选面板「达人」/「对标账号」 |
| 小红书 | 主页 + 作品页（登录态可用） | 平台内搜索、web 搜索 `site:xiaohongshu.com` |
| 快手 | 主页（作品流入口待核实） | 平台内搜索 + web 搜索 |
| 视频号 | 主页（作品流入口待核实） | 平台内搜索 + web 搜索 |
| B站 | **不要 fetch 视频页**（返回 -352 / 验证码） | web 搜索取 UP 主公开数据、三连量级 |
| 知乎 | 主页 / 回答页多可直取 | web 搜索补全 |
| 公众号 | 文章可读，账号页难取 | 搜文章标题聚合，推断更新频率与选题 |

**「待核实」的意思是「还没找到入口」**，不是「读不到」—— 找到入口就回填
`hamuna platforms <id> --json` 里的 `benchmarkEntry`，并记进 `memory/topics/<平台>.md`。

## 降级时的表述规范

反爬导致数据缺失时，结论里明确写清：

- 标注数据来源与可信度：`（来源：主页直取）` / `（来源：公开搜索，量级估算）` / `（无公开数据）`
- 缺失精确值时给区间或量级，例如"粉丝 10w+ 量级"而非编造"粉丝 112,384"
- 样本分析注明覆盖范围："基于近 20 篇样本，非全量"
- 绝不把推断包装成抓取结果——诚实比精确更重要

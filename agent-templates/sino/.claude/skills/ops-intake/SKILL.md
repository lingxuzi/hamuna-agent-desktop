# ops-intake — 物料入库

人往运营里投的只有两样东西：**原始物料** 和 **要宣传的产品**。这个 skill 只做一件事：
让台账知道 `ops/materials/` 里每个文件**是什么**。做稿是 `ops-produce` 的事，成品记录
（`asset`）也在那儿建。

## 为什么物料要单独记一条

文件名不携带语义。`IMG_2043.jpg` 到底是产品正面、包装盒、还是竞品参考图，只有人知道；
Agent 读不出来，只能在写脚本时猜——猜错就是整条内容拍错方向。

台账里的一条 `material` 就是这个语义：`path` + `note`（这是什么）。它**没有状态机**：
原料不会「制作中」，也不会「ready」。原料和成品的面板指标混在一起时，刚上传的十张图
会把「制作中」撑到 11，真正在做的那条被淹没。

## 开工前先读

```bash
ls ops/materials/                    # 盘上有什么（以盘为准）
hamuna ops list material --json      # 台账里已经记了哪些
```

盘上有、台账没有的文件就是**这一轮的活**。反过来（台账有、盘上没有）说明文件被删了或
挪走了，报给人，别自己删记录。

## 目录约定

```
ops/materials/
  1.jpg 2.jpg        # 产品图
  门店实拍.mp4        # 实拍
  brief.md           # 批次说明（可选，人写的自由格式）
```

**目录是平的，一个文件一条记录。** 不要按批次建子目录：一条记录描述一个文件，
合成「一批」就又回到「Agent 不知道哪张图是哪个」的原点。

`brief.md` 是人写给人看的自由格式，里面常有产品名、卖点、禁用词、平台。读完**把原文**
塞进相关物料的 `--brief-file`（见下），不要摘编——摘两次会不一样。

## 入库

对每个**还没有记录**的文件：

```bash
hamuna ops add material --path ops/materials/1.jpg --note "折叠桌正面产品图"
```

- `--path` 必填，必须是工作区相对路径（`ops/materials/…`）。文件名由后端从路径末段推，
  不用传。
- `--note` 写「这个文件是什么」，写给人也写给 Agent 看。**不知道就不传**，空着比编一个
  「大概是张图」好——编出来的描述会被下一轮当成事实。
- `brief.md` 的内容用 `--brief-file ops/materials/brief.md` 附上（原文，不改写）。

已经有记录的不要重建，改描述用 `update`：

```bash
hamuna ops update material --path ops/materials/1.jpg --note "折叠桌正面，主图用这张"
```

天然键是 `path`：同一路径重复 `add` 会合并成一条。

## 描述谁写、谁不能写

`noteSource` 由**写入门**决定，调用方传不了：

| 门 | 记成 | 含义 |
|---|---|---|
| 运营面板（人输入框） | `user` | 人说的话，可以直接当事实 |
| `hamuna ops`（我） | `agent` | 我的推测，下一轮只能当线索 |

所以**人还没写描述的文件，我可以先扫一遍填上**，但我填的东西会带 `agent` 标记，
下一轮我不会把它当事实用。这是设计的一部分，不是缺陷：

- 人写了 → 我改了 → 记 `agent`（最后一次写的是我）。
- 我没写、人写了 → 记 `user`。
- 人写的描述我原样重传 → 作者不变（不算我改的）。

**只在有人在场时扫。** 心跳 / 定时任务里别扫：那是无人值守的轮次，写进去的描述没人
纠正，会沉在台账里冒充事实。

## 判断不出是什么的时候

先看同目录的 `brief.md`；再看文件名和扩展名；还判断不出就**留空并问人**：

> `ops/materials/` 里新进来 3 个文件：`1.jpg`（已标成折叠桌正面）、`2.jpg`、`门店实拍.mp4`。
> 后两个是什么？一句话就行。

一次问完，不要一个文件一轮。

## 不要做

- **不要建 `asset`。** 物料不是成品：没有 `form`、没有 `progress`、没有状态。素材由
  `ops-produce` 建。
- **不要搬文件。** 物料就留在 `ops/materials/`；成品才落 `ops/assets/<assetId>/`。
- **不要替人改 `brief.md`。** 那是人的输入，改了就失去意义。
- **不要为了「台账看起来完整」给每个文件都编一句描述。** 空描述是诚实的「还不知道」。
- **不要直接编辑 `ops/state.json`。**

# ops-topic — 选题

选题是四段循环的第一段。它的产出**只是一条记录**：做什么、为什么值得做、从哪个角度切、打哪个平台。写成内容不是这一步的事。

## 开工前先读

```bash
hamuna ops list --json          # 现在手上有什么，别重复提
hamuna ops list rule --json     # 复盘沉淀的规律，选题要顺着它们走
```

读 `.claude/rules/05-OPS.md` 里的数字口径，尤其 `hotness`。

**规律会过期。** `ops list rule --json` 里每条规则带 `freshness`：

| `freshness` | 能不能当筛选条件 |
|---|---|
| `fresh` | 能 —— 但它是**上一轮**的结论，这轮的数据还没对过 |
| `stale` | **不能**。依据过期了，面板也不会再推荐它 |
| `unknown` | 只能参考。没记采样时刻的老规则，不知道多久了 |

过期的规则能给你「当时好像是这样」的线索，不能当铁律。按一条过期规则做的选题，
不是「按规律做的」，是「赌那条规律还成立」—— 真要赌，就在 `--note` 里写清赌的是什么。

## 输入源

按可信度排：

| 来源 | 怎么拿 | `source` |
|---|---|---|
| 平台公开热榜 | `hamuna browser open <热榜URL>` → `hamuna browser read`，读返回的 markdown；或 web 搜索「XX 平台 热榜 今天」 | `hotspot` |
| **台账里的对标账号** | `hamuna ops list benchmark --json` 拿到主页链接 → `hamuna browser open <主页URL>` → `hamuna browser read`。**只读公开页，不用登录态进别人后台** | `benchmark` |
| **拆过的对标账号** | `hamuna ops list rule --json` 里 `source: benchmark` 的规则 —— 拆解产出的结论（爆款选题类型、封面模板、互动结构）。台账里没拆过就读主页 | `benchmark` |
| **台账里的评论线索** | `hamuna ops list clue --json` —— 观众在我们自己作品下面问过的东西（「这个多少钱」「哪里买」「怎么用」） | `benchmark` |
| 用户直接给的线索 | 用户粘贴的链接、截图描述、一句话 | `manual` / `benchmark` |
| 上一轮复盘的结论 | `ops list rule` 里的 `active` 规则（`freshness` 不是 `stale` 的） | `reflection` |

**采集边界**：公开热榜、公开主页、用户粘贴的内容可以读。他人账号后台、私域数据、需要登录才能看到的东西不碰。

**`source: benchmark` 的规则只能当线索，不能当筛选条件。** 它描述的是**对手**在做什么，
不是我们该照抄的 —— 抄之前先分清「他这么做有效」和「他这么做是因为他这么做」。
想不清楚就当这条规则不存在。我们自己的复盘验证过、那条 rule 的 `status` 转 `active` 之后，
才配当筛选条件。

**用对标账号时必须指名**：一条 `source: benchmark` 的选题要说清是**哪个对标账号**的什么内容给了启发，
写进 `--ref`（主页链接）和 `--note`。写「参考了对标账号」等于没说 —— 下一轮没人知道该去看谁。

**用线索时必须指名**：说清是哪个问题（几个人问、问了什么）。「最近有 3 个人问价格」比「用户关心价格」有信息量得多。

**用内嵌浏览器，不用系统浏览器。** `hamuna browser open` 打开的是 App 内嵌 webview（`hamuna browser read` 能把当前页读成 markdown），页面留在 App 里用户看得见，采集过程透明。打开失败（浏览器面板不可用）就退回 web 搜索，不要反复重试。

## 判断值不值得做

分两步：**先过四道硬门，过了门再打分**。顺序不能反——四门不过的选题，打多少分都不做。

### 四道硬门（任一不过，直接毙，不打分）

1. **和这个号的定位有关** — 读 `03-USER.md` 的赛道。不相关再好也不做。
2. **有差异角度** — 同样的题材已经被讲过八百遍，我要说的是哪一句不一样的话。
3. **现在做还来得及** — 热点有半衰期，超过 72 小时的"热点"通常已经是旧闻。
4. **做得出来** — 手上的素材、时间、能力够不够。够不着的选题不是选题，是愿望。

### 七维打分（过了门才打）

每维 1–10。**制作成本**和**合规风险**是反向维度：分越高代表越省事、越安全，
这样七维能直接相加。

| 维度 | 权重 | 1–3 分 | 4–6 分 | 7–8 分 | 9–10 分 |
|---|---|---|---|---|---|
| 流量潜力 | 25% | 小众冷门，痛感弱 | 有热度，同类有稳定流量 | 热门话题或踩中时效 | 全民级，或精准戳中大体量刚需 |
| 账号匹配 | 20% | 完全偏离定位 | 有关联但要跨领域 | 与核心定位相关 | 正中最强领域 |
| 竞争差异化 | 15% | 同类 >100 条，无新角度 | 有竞争但角度可切 | 竞争适中，有明显空白 | 几乎无同类优质内容 |
| 变现潜力 | 15% | 纯娱乐，接不了任何东西 | 只能做品牌背书 | 可自然接商单或带货 | 高客单 / 高转化品类 |
| 时效价值 | 10% | 已过时或即将过时 | 一周内有效 | 常青 + 时效双重 | 常青，长期有搜索价值 |
| 制作成本（反向） | 8% | 要专业设备 / 外景 / 多人 | 要备素材，个人能完成 | 只要文字或简单拍摄 | 纯文字 / 口播 / 已有素材 |
| 合规风险（反向） | 7% | 高危赛道，易限流 | 有敏感点要谨慎措辞 | 轻微风险，规避即可 | 无风险 |

综合分 = Σ(维度分 ÷ 10 × 权重 × 100)。

| 综合分 | 怎么做 |
|---|---|
| ≥ 70 | **提**。这就是能提的那条 |
| 50–69 | **改方向再算一次**：换角度 / 换形态 / 换时机，改完还进不了 70 就不提 |
| < 50 | **不提** |

敏感赛道（医美、理财、母婴、K12、健康养生、护肤功效、职场收入、婚恋）在合规风险
上老实扣分，别给面子分。

**分数要落在台账里。** `--note` 写成「七维 82：流量 8 / 匹配 9 / 差异 7 / 变现 6 /
时效 8 / 成本 9 / 合规 10 —— 为什么值得做」这一种格式。下一轮复盘时才知道
当时是按什么判断的，也能看出哪个维度一直给低了。

**宁可不提，也不提一条你其实不看好只是为了凑数的。**

## 落库

```bash
hamuna ops add topic \
  --title "选题标题（用户能看懂的一句话）" \
  --platform douyin \
  --source hotspot \
  --angle "切入角度：我这句不一样的话" \
  --note "为什么值得做：和定位的关系 + 现在做还来得及的理由" \
  --hotness 86000 \
  --tag 职场 --tag 反常识 \
  --ref "https://参考内容链接"
```

字段规则：

- `--title` 是用户能在面板上一眼认出这条选题的标题，不是内容标题的草稿
- `--platform` 只能是 `xiaohongshu` / `douyin` / `kuaishou` / `weixin-channels` / `bilibili` / `zhihu` / `wechat-mp`
- `--hotness` 填**参考内容的播放量**（整数）。没有可比的参考内容就**不传**——传 0 会被当成播放量为零
- `--tag` / `--ref` 可以重复传多次
- 不加 `--status`，新建默认 `idea`

**一次最多提 3 条。** 提 20 条等于没提。

## 交接

提完把 id 报给用户，一句话说清每条的核心判断（不是复述标题）。用户点头后进 `ops-produce`。

## 不要做

- 不要在这一步写正文、画封面。那是 `ops-produce` 的事。
- 不要改已有选题的状态——那是用户在面板上按的检查点。
- **不要直接编辑 `ops/state.json`。**

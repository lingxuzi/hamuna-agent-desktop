# ops-topic — 选题

选题是四段循环的第二段：**`ops-signal` 产出热点简报 → `ops-topic` 决定做不做 → `ops-produce` 做内容**。

它的产出**只是一条记录**：做什么、为什么值得做、从哪个平台来、参考是什么。
真正写不写、写成什么样，在 `ops-produce`。

## 开工前先读

```bash
hamuna ops list direction --json   # 账号定位：七维里「账号匹配」的基准
hamuna ops list topic --json       # 现在有什么选题、哪些角度已经做过
hamuna ops list rule --json        # 复盘沉淀下来的规律
```

读 `03-USER.md` 拿平台清单和赛道。`source`、`status`、`platform` 的口径见 `05-OPS.md`。

没有 `direction` 时先跑 `ops-direction` 定方向，不要在没定位的情况下批量出题。

## 输入从哪来

| 输入 | 从哪来 | 怎么用 |
|---|---|---|
| 热点简报 | `ops-signal` | 热点候选的阶段 / 关联度 / 角度 / 风险 / 原始链接已经判过；这里只做选题决策，不重扫榜 |
| 评论线索 | `ops list clue --json` | 未处理的 `intent=topic` 线索，优先看；它们是观众自己说想看的 |
| 对标账号 | `ops list benchmark --json` | 看对手最近在做什么、哪里能做出差异 |
| 复盘规律 | `ops list rule --json` | 只拿 `active` 且验证过的规则当硬约束；`draft` 只是提醒 |
| 用户直接给的题 | 对话 | 用户点名的题目，跳过发现，直接进判断 |

**没有热点简报时，不要自己去扫热榜。** 需要热点输入就先跑 `ops-signal`（交互式）或等定时任务产出的简报。后台 / 定时场景没有浏览器面板，扫榜通道和约束见 `ops-signal` skill 的 `hotlist-sources.md`（该 skill 的 references/ 目录）。

## 选题怎么来

1. **热点简报**。拿 `ops-signal` 给的候选，逐条过下面的四道硬门和七维打分。简报里已经标「不建议蹭」的，不要重新捞回来硬做，除非你有新的证据推翻原判断——推翻时把证据写进 `--note`。
2. **评论区线索**。`ops list clue --status new --json` 里 `intent=topic` 的条目，是观众直接告诉你的需求。用完把线索标成 `used` 或 `archived`。
3. **对标拆解**。扫对标账号最近发了什么，找能借的角度。拆法见 `ops-benchmark-analysis`。
4. **存量裂变**。从自己跑赢过的选题里换角度再做一条。前提是那条选题已经有复盘结论，不能凭感觉复刻。
5. ** evergreen 储备**。不过时的选题，攒着等内容荒的时候顶上。

热点来的题标 `--source hotspot`，并带上 `--ref <热点简报里的原始链接>`。`--hotness` 只填参考内容的**播放量**；热榜热度值不是播放量，不填。

## 四道硬门

候选题逐条过，**任一不过就毙，不进打分**：

| # | 门 | 不过的信号 |
|---|---|---|
| 1 | **关联度** | 这题跟我这个号的定位搭不上边。硬蹭只会让观众困惑。`ops-signal` 已判低 / 无的热点默认不过，除非有新证据。 |
| 2 | **差异化** | 同题材别人已经讲烂了，我没有新角度 / 新信息 / 新表达。 |
| 3 | **可行性** | 需要的素材、权限、时间现在没有，或者做出来也赶不上。 |
| 4 | **合规** | 平台会限流、封号，或者有法律 / 品牌风险。 |

四道门过了才值得花时间打分。门都没过的题，不要记进台账「留着以后看」——那是垃圾堆。

## 七维打分

过了硬门的题，七个维度各 1–10 分：

| 维度 | 问什么 |
|---|---|
| 账号匹配 | 符合 `direction` 定的调性、受众、禁区吗？ |
| 受众需求 | 目标观众真的想看这个吗？有搜索量 / 评论问过 / 私信求过？ |
| 竞争度 | 同平台同题材已经有多少条？头部的效果怎么样？ |
| 制作成本 | 要多久、要多少素材、要不要外援？ |
| 变现潜力 | 能带来关注、转化、还是纯消耗？ |
| 时效性 | 现在发和下周发差多少？热点题过了窗口就作废。 |
| 可扩展 | 能不能裂变成系列？一条题能不能长出三条？ |

**不设总分阈值。** 七维里任何一维 ≤ 3 分，单独拎出来说清楚为什么还要做；说不清就毙。

## 落台账

```bash
hamuna ops add topic \
  --title "用一句话说清这条要讲什么" \
  --platform douyin \
  --source hotspot \
  --competitor "可选：对标账号 / 对标内容" \
  --ref "https://原帖或热点链接" \
  --hotness 86000 \
  --note "为什么值得做；七维里哪个维度最强 / 最弱"
```

- `--source` 从 `hotspot | manual | system | clue | evolution` 里选。
- `--platform` 是这条选题**计划发在哪个主平台**。
- `--hotness` 是参考内容的**播放量**。没有可比参考就不传；**热榜热度值不是播放量，也不传**。
- `--note` 写判断，不写废话。下一轮复盘会读它。

## 提给用户

提完把 id 报给用户，一句话说清每条的核心判断（不是复述标题）。用户点头后进 `ops-produce`。

## 不要做

- **不要扫热榜。** 热榜采集、阶段判断、关联度 / 风险初判属于 `ops-signal`。
- **不要在这一步写正文、画封面。** 那是 `ops-produce` 的事。
- **不要改已有选题的状态。** 那是用户在面板上按的检查点。
- **不硬凑热点。** 简报里已经判低 / 无关联的，不要重新包装成「其实有关」。
- **不要直接编辑 `ops/state.json`。**

## 我们在哪一档

阶段按**粉丝量级**分。**粉丝数是平台上的数，不是台账里的数。**

```bash
hamuna platforms <id> --json       # 拿 creatorHomeUrl（自己号的创作者后台）
hamuna browser open <creatorHomeUrl>
hamuna browser read                # 粉丝数在后台首页的概况栏
```

读不到（没登录态 / 页面改了）就**问用户一个数**。Easel 那边也是靠问 —— 别自己估。

还没发过任何内容 = 0 档，不用去读后台。

**别拿复盘里的 `metrics.followers` 当粉丝总数。** 那是**一条内容**带来的净增
（`ops-review` 的口径），不是账号的量级 —— 把单条的 +30 读成「当前 30 粉」，
档位就永远停在 0-500，跨档也发现不了。

| 阶段 | 粉丝量级 | 特征 | 核心任务 |
|---|---|---|---|
| 0-500（冷启动） | 0-500 | 无稳定推荐 | 打磨垂直度、跑通「能被推荐」的基础内容、明确定位 |
| 500-5k（起量） | 500-5k | 偶有小爆 | 找到可复制的内容模型、稳定更新节奏、强化钩子 |
| 5k-1w（放大） | 5k-1w | 有稳定推荐 | 批量复制爆款结构、做系列化、提升关注转化 |
| 1w+（沉淀） | 1w+ | 有粉丝基本盘 | 私域/变现、矩阵、粉丝深度运营 |

## 分阶段起号动作（示例锚点，按定位调整）

- **0-500**：定位收窄到一个细分 → 对标 3 个同层账号拆结构 → 用统一选题方向发 10 条测试 → 观察哪类进小流量池。
- **500-5k**：把测试出的高互动模型固化成模板 → 固定更新节奏 → 每条强化前 3 秒钩子。
- **5k-1w**：系列化 + 爆款结构复用 → 主页/结尾优化关注转化 → 开始沉淀选题库。
- **1w+**：私域引流 / 变现路径 / 矩阵铺号。

## 一处必须改的：同层对标

Easel 那句「对标 3 个同层账号」，在 sino 里**没有现成的一档**。

台账里的 `benchmarks` 记的是**方向相近**的号，规模通常**更大**（`ops-benchmark` 的定义）。
规模写在 `evidence` 里（不单独存字段 —— 存了就是会过期的数字）。

所以 0-500 这一档要拿「同层参照」时：

- 先在 `hamuna ops list benchmark --json` 的 `evidence` 里读规模，量级接近就用；
- 不接近就按 `ops-benchmark` 补一个**方向相近且量级接近**的号，那才叫同层；
- 实在找不到同层的，用方向相近的大号拆**打法**（爆款选题类型、封面、钩子、节奏），
  但**别拿他的量级当自己的起号路径** —— 他 0→500 那段看不到，平台那几年也早变了。
  能借的是打法，不是他的历史。

## 这一档的出口

0-500 的处方落成「**前 10 条测试**」：统一一个选题方向发 10 条，看哪类进了小流量池。

**有几条进了小流量池，这一档就过了。** 一条都没进，换方向再测一轮 ——
不是加量，是换变量。10 条里塞 3 个方向，等于什么都没测出来。

# ops-signal — 热点

这是「热点 → 选题 → 内容」的第一段。**只做一件事：把今天值得看的热点挑出来，判断它值不值得往下走。**

产出是**一份简报**，不是台账记录。落 `topics` 是 `ops-topic` 的事。在这里建选题，会让选题跳过四道门和七维打分。

## 开工前先读

```bash
hamuna ops list direction --json   # 每个平台的定位：判断关联度的依据
```

读 `03-USER.md` 的赛道和平台（主战场 / 分发平台）。没有方向时先说「方向还没定」，别凭感觉判断关联度。

## 两条取数通道

| 场景 | 怎么取 |
|---|---|
| 有浏览器面板（人在 Chat 里） | `hamuna browser open <热榜URL>` → `hamuna browser read` |
| 定时任务 / 后台（没有面板） | `curl` 打 newsnow 聚合接口 |

**「有面板」不是「有个定时任务在跑」。** 模板不预置扫榜 cron；无人值守轮次（心跳 / IM）
只是恰好没面板，用 `curl` 那条，不代表有个任务定期把简报准备好了等着你读。

榜源、URL、newsnow 的域名 / UA / 可用 id / 缓存，全部在 `references/hotlist-sources.md`。**不要凭记忆拼域名，不要换没核实过的接口。**

## 一次扫多少

- 只扫主战平台的榜；默认 2–3 个，单平台号只扫自己那个平台。
- 一轮扫一次就够；榜 5–10 分钟刷新，反复刷拿不到新信息。
- 扫不到就说「榜没取到」，不要把它说成「今天没热点」。

## 判断（四件事）

对每个候选热点，按 `references/hot-riding.md` 判：

1. **阶段** — 爆发期（0–4 小时）/ 高峰期（4–24 小时）/ 衰退期（24–72 小时）/ 长尾期（72 小时以上）。边界只定义在 `references/hot-riding.md` 一张表里，这里不重复。
2. **关联度** — 高 / 中 / 低 / 无。依据是 `03-USER.md` 的赛道 + `direction` 的定位。低 / 无直接标「不建议蹭」，并给一个替代方向。
3. **角度** — 六种切入角度（专业解读 / 经验关联 / 工具方法论 / 反向观点 / 情绪共鸣 / 延伸联想）里挑 2–3 个，写成「哪一句不一样的话」，不是只写分类名。
4. **风险** — 政治 / 法律 / 舆论反转 / 道德争议 / 平台规则，逐条过。有一条过不去就不提。灾难、事故、逝世类默认不蹭。

**热度等级（S / A / B / C）写在简报里**，它是判断依据，不是台账字段。

## 输出：热点简报

一轮只出一份，按下面的形状交给 `ops-topic`：

```markdown
## 热点简报 YYYY-MM-DD HH:mm

| # | 热点 | 来源 | 阶段 | 关联度 | 热度 | 可选角度 | 风险 | 结论 |
|---|---|---|---|---|---|---|---|---|
| 1 | … | 抖音热榜 #3 | 高峰期（6h） | 高 | A | 专业解读 / 经验关联 | 无 | 建议做 |
| 2 | … | 微博热搜 #1 | 爆发期（1h） | 低 | S | — | 道德争议 | 不建议蹭，替代方向：… |

### 候选详情
- **#1 …**：为什么关联、这个阶段该抢什么、推荐角度的那一句话、可引用的公开来源链接。
```

**简报里必须有原始链接**（热榜条目 URL 或平台原页），下一段选题要写进 `--ref`。没有链接的热点，等于让下一段去猜。

**不要在这份简报里打七维分。** 打分是选题的活；热点只回答「值不值得进入候选池」。

## 交接

把简报交给 `ops-topic`，一句话说清「这批里最值得看的是哪 1–2 条，为什么」。选题会拿它和台账里的线索、历史、对标一起排，过四道硬门、打七维分，再决定落不落库。

### 简报不落盘，只同轮传递

**没有简报文件，也不该有。** 热榜 5–10 分钟刷一次、热点半衰期 0–4 小时 —— 一份存下来的
简报，到下一个会话开始时基本只剩「昨天在聊什么」这一个用途，而它看起来和今日的榜一模一样。
拿它去选题，产出的是一条过期选题，且没人看得出。

所以：会话结束，简报就结束。下一轮选题没有简报 = **重扫一遍**，代价是一次
`browser open` + `browser read`，几秒钟的事，换一份真的榜。

要留就留台账里的那条 `topic`（`--note` 写清当时的阶段 / 热度 / 关联度 / 风险）——
那是决策记录，会跟着选题一起进复盘。简报本身是过程物，不是记录。

## 不要做

- **不建选题。** 不跑 `hamuna ops add topic`；那是 `ops-topic` 的事。
- **不写正文、不画封面、不排期、不发布。**
- **不硬凑热点。** 关联度低 / 无就明说，并给替代方向。
- **不读别人作品的评论区。** 热点采集只读公开热榜 / 公开主页 / 用户贴的内容。
- **不在无人值守场景用 `browser open`。** 没有面板就换 `curl`；别等一个永远不会有人开的面板。
- **不把热榜热度值当播放量。** `--hotness` 的口径是参考内容的播放量；简报里写榜位和热度等级，不写假播放量。

## 一、方向卡

| 项 | 决定 |
|----|------|
| **北极星** | 运营面板要让人**一眼看出「这是同一个循环在转」**——复盘产出的规则回到选题，选题变成素材，素材排成时间，时间又变成复盘数据。四域不是四个抽屉，是一条闭环上的四段。 |
| **品类** | 桌面 Agent 应用内的运营工作台（非独立 dashboard） |
| **用户来首屏看什么** | Agent 现在在做什么 + 我该在哪个检查点介入 |
| **同类最好怎么做** | dsh-media-desk（`/home/hmcz/Projects/referer/dsh-media-desk`）：Hero 一句话结论 + 指标带 + 深墨主角卡 + 卡片网格，一屏给结论再给证据 |
| **调性** | 结论先行 / 疏松 / 有呼吸。用**仪表盘语法**装**运营叙事** |
| **借鉴 vs 重做** | **外观与结构整套借鉴 dsh**（Hero 结论句、指标带、胶囊导航、深墨主角卡、卡片网格）；**配色整体重做** —— dsh 的淡紫粉弥散与蓝色折线是它自己的主题，落到 app 里一律走 app 主题 token |

### 已解决的矛盾

dsh 是 1400px 全屏插件（淡紫粉弥散 + 蓝色折线）；运营视图是 **380–600px、暖纸色的聊天侧栏**。

- **直接照搬外观**：面板会像贴上去的外来物，和 Chat 页其余部分割裂。
- **照搬结构、不照搬色值**：Hero 结论句、指标带、胶囊导航、深墨主角卡、卡片网格这些**结构语法**跨主题都成立；淡紫粉与蓝色属于 dsh 的主题。

**定案**：结构照搬，配色换成 app 自己的暖纸色系，两色相分工：

| 色相 | token | 承担 |
|------|-------|------|
| 陶土（暖） | `--accent-warm` `#c26d3a` | 交互、状态、活跃项、进度 |
| 深青（冷） | `--accent-cool` `#2e6f5e` | 数据、**回流**（复盘 → 选题）、图表、条形 |

冷暖对位是这份配色唯一的"炫"点：全暖会闷，全青会冷，两个色相都在 app 现有调色板里，不新增颜色。dsh 的淡紫粉弥散换成同位置的暖色弥散。

## 三、动效（三处）

三处动效的共同前提：**动的是「状态」，不是「装饰」**。

1. **入场递进** — Hero 与卡片整体 rise（元素 160ms + 延迟 40ms = 整场 **200ms** 封顶）。切域重放。让「Agent 刚更新过」可感知。
2. **状态脉冲** — 深墨主角卡右上角的圆点 1.8s 循环，`box-shadow` 扩散。这是**唯一持续动画**，克制到只剩一个点。
3. **纹理与光晕（静态动势）** — 面板底是 app 自带的点阵纹理 + 右上一抹暖光晕（`oklch(78% 0.04 45 / .3)`，抄 `--theme-body-background` 的做法），不用紫色弥散圆晕那种 AI 工具套路。

任一域的卡片进出场都走同一套，不按域分化——换域时的观感必须是「同一块面板换了内容」，不是「跳到了另一页」。

## 四、方向 D · dsh 复刻（选定）

参考项目 dsh-media-desk 的**外观与结构整套采用**。四个域共用一副外壳，切域换的是整套内容。

### 四个域怎么排

| 域 | Hero 结论句 | 三条指标 | 主列表 | 分布卡 |
|---|---|---|---|---|
| 选题 | 几条待加工 + 来源构成 + 先做哪条 | 待加工 · 已产素材 · 热点来源 | 选题池（按优先级） | 来源分布 |
| 素材 | 在制几条 + 卡在哪 | 制作中 · 待排期 · 本周完成 | 制作中（按滞留时长） | 状态分布 |
| 排期 | 本周几条 + 哪天空着 | 本周待发 · 待排期 · 空缺日 | 本周（按时间） | 平台配额 |
| 复盘 | 已发几条 + 最好的哪条 | 总播放 · 总互动 · 平均完播 | 表现最好的内容 | 平台分布 |

**指标带按域换口径，这是把 D 铺到四域时唯一真正要重推的东西。** dsh 的句式是量化仪表语法（「12 条内容带来了 18.2 万次播放」），照抄到选题域会变成假仪表盘——选题是还没做的意图，根本没有播放量。所以句式保留、口径按域实配。

**只有复盘域有两张额外卡**：每日趋势折线（只有复盘有可画的时间序列）与「给你的建议」（只有复盘有数据可提炼，且建议的落点是**回写选题规则**，正好是闭环的回流边）。其余三域不渲染这两张卡。

**深墨主角卡同一张，换文案**：复盘是「领跑优势 +4,435」、排期是「下一条 11/14」、选题是「最优先 ×8,412」、素材是「最该收尾 1 条」。

### 语法 → token 映射

| dsh 外观元素 | app 里的落地 | 代价 |
|-------------|---------------|------|
| Hero 一句话结论 + 右侧指标带 | 保留。标题 28px，数字走 `--font-serif-family` | dsh 用 40px 巨号衬线，app 七档上限 28px，**气势弱一档** |
| 淡紫粉弥散光晕 | 换暖色弥散 `oklch(80% .05 52 / .5)` | 无 |
| 胶囊导航（选中态实心） | 保留胶囊形状；选中用 `--button-dark-bg` 深墨 + 白字 | 无（对比度 15:1） |
| 蓝色折线 / 条形 | 换 `--accent-cool` 深青 `#2e6f5e` | 无 |
| 黑色「下一条」主角卡 | 换 `--button-dark-bg` 深墨卡 | 无 |
| 白卡 + 淡边 + 圆角 20 | `--paper-elevated` + `--line` + radius 14 | 圆角从 20 降到 14（app 档位内） |

### 宽窄两版

同一份 DOM 用**容器查询**自动切换，不做两套 HTML。断点 760 / 400 两档：

- **760 以下**（含全部落地宽度 380–600）：摊平成一列。走的是 `display: contents` 把「主区 / 右栏 / 网格」三层拆开，再用显式 `order` 把各卡片交错排成：Hero → 深墨主角卡 → 主列表 → 图表 → 分布 → 建议 → 要点。窄栏下「主区 + 右栏」横排会把主区压到只剩 190px，Hero 被挤成竖排单字，所以必须摊平。**`order` 只声明在这个断点里**——放外面会让宽栏主区（flex 列）也按 order 排，Hero 跑到网格后面。
- **400 以下**：390/380 放不下「域胶囊 + 导出 + 助手」三件，砍掉「导出」；标题从 28 降到 22（字阶内），产品名整体不拆行；三个导入动作从横排改单列全宽等高（否则排成 2+1 的残局）。

### 宽栏网格的落位

复盘域四张卡排成 2×2（左上折线跨宽列、右上分布；左下排行、右下建议）。非复盘域只有两张，显式指定 `grid-column` 让**主列表占宽列**——靠 DOM 顺序会让分布卡占掉宽列、主列表被挤进窄列，正好反过来。这个开关用 Alpine 挂的 `.dsh-grid-2` class，不用 `:has()`：`:has()` 要 WebKit 15.4+，而这份稿要被人抄成 React，不埋隐性版本要求。

**右栏两张卡不吸底**，直接贴着排。试过 `justify-content: space-between`（顶卡贴顶、末卡贴底），宽屏下它把两张卡拉开 400px 的空带，比留白更像出错；也试过给末卡 `flex: 1`，那会得到一张 3/4 空的大卡。留白统一落在内容之后。

600px 属于落地区间，所以**保留「导出」**——这是首轮修正的返工点：初版把断点设成 760 并让「导出」在这个断点消失，等于整个 380–600 区间都没有导出，而 600px 顶栏右侧还有约 280px 空位。

### 落地参照怎么读

**以 600px 那一版为准，1264px 那版只当结构图。**

两版同源（同一份 DOM + 容器查询），token / 字阶 / 色块 / 衬线数字 / 深墨卡全都一致，所以外观语言可以整体照搬进右栏。但有四处宽窄落差会误导实现：

1. **右栏那一列在落地区间不存在。** 600px 下「主区 + 右栏」竖排会把主区压到只剩 190px，所以照宽屏拼双栏会把主区挤死。
2. **Hero 只有纵向那版被验证过。** 宽屏是「左文案 + 右 KPI 同行」，600/390 是「文案 → 动作 → KPI」三段纵向。
3. **深墨卡的角色变了。** 宽屏它是右栏视觉锚点（内容 = 与第 2 名的差距），窄栏它是紧跟在 Hero 后的独立块。
4. **导出只在 ≥401px 存在。**
5. **宽栏的 2×2 网格四张卡，窄栏是七段单列**——四域各自的卡片数量不同（复盘五张、其余三域三张），两种形态都要能在切域时不跳。

### 落地取舍

D 是**整页**语言（dsh 是 1400px 全屏插件），我们要放进 380–600px 的聊天右栏。整页语言照搬，但有三处按窄栏重排：

1. **主区 + 右栏的双栏在落地区间不存在**——摊平成一列，深墨卡从「右栏视觉锚点」变成「紧跟 Hero 的独立块」。
2. **Hero 只有纵向那版被验证过。** 宽屏是「左文案 + 右 KPI 同行」，600/390 是「文案 → 动作 → KPI」三段纵向。
3. **导出只在 ≥401px 存在。**

**图表网格与 Top5 列表进了 D，但只有复盘域渲染**——它们属于复盘的分析视图；其余三域的主列表换成各自的对象（选题池 / 制作中 / 本周），不套用「Top5 排行」的语义。

### 独立评审与修正

盲审（只看画面 + 任务 + 约束，不看制作过程）两轮，**首轮 7/10 → 复评 8/10**。两轮都在 D 还只有复盘域一页时做的；补齐另外三域后**未复评第三轮**，下面「到 10 分还差什么」按原样留着。

首轮扣分集中在「复盘的可信度」而不是外观：排行排序自相矛盾、图表没有尺度、建议没有依据、右栏混进了排期域内容。逐条处理如下。

| 评审项 | 处理 |
|--------|------|
| 排行数值错位（5,930 排在 6,930 之上）、右列无单位 | 重排为严格降序，右上加「播放」列头；平台分布也从「8.0 万」改成同单位的次数，两张卡一套读法 |
| 图表无纵轴，量级读不出来 | 补纵轴 0 / 1.5 万 / 3 万 + 峰值标注「峰值 2.7万」。刻度与网格线共用同一组 y 值（12 / 83 / 154），标签绝对定位，避免两端对齐时错位 |
| 建议是断言不是洞察 | 每条建议下挂一组对照条（封面有数字 1.8× vs 无数字 1.0×；直给结果 49% vs 铺垫开场 29%），结论当场成立 |
| 字牌用了两个主题外色相，且白字不过 AA | 字牌去掉色相，改中性底 + 深墨字。色相本身无语义（同一个「早」出现两次却不同色），白字压在陶土 / 橄榄 / 蓝灰上只有 2.6–3.8:1。真实封面接 `tool_attachment` 管道，落地阶段再补 |
| 复盘 tab 里出现排期域内容 | 右栏换成复盘域：深墨卡改「领跑优势」，托盘改「复盘要点」。「下一条 + 待排期」归排期 tab，同一张深墨卡换个文案即可 |
| 窄栏第一屏看到的是图表，不是排行 | 窄栏顺序改为 Hero → 领跑优势 → 排行 → 图表 → 平台分布 → 建议 → 复盘要点。600×780 首屏能看到排行前 4 行 |
| 右栏卡片底部空 1/3 | 网格改 `align-items: start`，卡片按内容高度，不再被同行高卡片撑出空底 |
| 排版细节 | 「18.2 万」与「18.2万」两种排法统一为「数字 + 小字单位」；裸圆点换成真图标（导入 / 编辑 / 表格 / 加号）；三个 KPI 从等分栅格改 flex 固定 gap（栅格右对齐时间距仍随数字宽度变）；平台分布与排行榜统一发丝线节奏；「写进规则」描边加一档 |

复评（8/10）确认首轮五项全部闭合，并指出**修正本身引入的 9 个新问题**。逐条处理：

| 复评新问题 | 处理 |
|-----------|------|
| **导出在整个落地宽度消失**（断点 760 盖住了 380–600） | 断点拆成 760（布局）/ 400（顶栏与标题）。600px 保留导出；只有 ≤400px 才让位 |
| **390px 首屏把产品名拆断**（「次播放，」孤行、「早餐。」被劈开） | ≤400px 时标题 28 → 22，去掉写死的 `<br>`，产品名加 `nowrap` |
| **宽屏右栏下半段 580px 全空** | 右栏改 `justify-content: space-between`：深墨卡贴顶、复盘要点贴底，两端锚定。让某张卡 `flex: 1` 撑满会得到一张 3/4 空的大卡，比留白更抢眼，所以没那么做；「复盘要点」也从 3 条补到 5 条 |
| **窄栏首屏把第 1 名原样重复一遍** | 深墨卡从「本期领跑 12,847 / 早八人的早餐」改成「领跑优势 +4,435 / 第 1 名领先第 2 名 53%」——不再复述排行第 1 行，改成排行里读不出来的信息 |
| **动效证据三处不齐** | 三帧改用 `?freeze=<ms>` 精确定格（`t=0` / `64ms` / `400ms`，逐帧给出 opacity 与 translateY）；主操作反馈与胶囊切换在交付物里真的做了（见下）；reduced-motion 补 `t0.png` / `t800.png` 两张真 emulation 截图 |
| **reduced-motion 下 delay 没归零**，卡片仍按 40ms 级联闪出 | `base.css` 的降级块补 `animation-delay: 0s !important` / `transition-delay: 0s !important`。实测 t=0 时 7 张卡 opacity 全为 1 |
| **出场总时长 320ms，超 200ms 预算** | 单次 200ms → 160ms，延迟收成两档（0 / 40ms），整场 **200ms**。`shots/d-motion/verify.json` 写明 duration / delay，约束从证据里可核 |
| **深色强调色不是 token**（`#5ec49e` 自造） | 改用 app `--accent-cool` 的深色值 `#4aad8a`，不另造色 |
| **排行行身份编码太弱**（前两行都显示「早」） | 字牌加平台色块，与首字合成双编码：抖音=深青、小红书=陶土、视频号=深墨 |

复评还指出「主操作反馈、状态切换来路是**没做**，不是没拍到」。这一条按原样接受了——交付物里真的补上：

- **主操作**：点「导入账号数据」→ 按钮立刻缩放回执（`dsh-press` 200ms）→ 文字变「导入中…」并禁用 → 完成后底部弹出回执「已导入 12 条内容的数据」。
- **规则回写**：「写进规则」按下后按钮变「已写进规则」+ 勾选图标 + 深青描边，并弹出「已写进选题规则」。
- **状态切换**：胶囊切域后选中态迁移（深墨底 + 白字，200ms 过渡）。

评审判「可以保留、不要动」的五项（顶部胶囊条、深墨反白卡形态、排行三段式结构、平台分布条形、建议块的「结论 + 依据 + 动作」结构）两轮都原样保留，只改内容与位置。

把这一页铺到四域时，唯一真正要重推的是**指标口径**：四项照样搬会把另外三域做成假仪表盘（选题域没有播放量可读）。处理是保留 Hero 的句式、按域换三条指标——选题看「待加工 / 已产素材 / 热点来源」，素材看「制作中 / 待排期 / 本周完成」，排期看「本周待发 / 待排期 / 空缺日」，只有复盘保留播放 / 互动 / 完播。深墨主角卡同理：每域各给一个「这一域此刻最该看的那条」（最优先的选题 / 最该收尾的素材 / 下一条排期 / 领跑的领先幅度），而不是复用「+4,435 领先」。

### 到 10 分还差什么

复评给了 8/10，剩下的差距不在画布上：

- **hover / 按下态、滚动行为**在静态截图里没法验，得在真 React 组件里跑。
- **Windows / macOS 的真实字体与图标渲染**未验证（本机是 Linux + Chromium）。
- 排行行的**真实封面**要接 `tool_attachment` 管道，现在是字牌占位。
- dsh 的 40px 巨号衬线受 app 七档字阶（上限 28）压制，气势天然弱一档——这条是规范取舍，不是缺陷。

### 数值口径统一

原稿的卡片之间数字互相对不上（Hero 说 18.2 万，图表 15 天加起来 30 万，排行之和只有 3.7 万）。现在全局只用一套数字：

- **总量 18.2 万** = 平台分布四项之和（80,000 + 68,000 + 29,000 + 5,000）= 图表 15 天日播放之和（峰值 2.7 万）。
- **排行严格降序**，榜首 12,847 落在图表峰值之内。
- **平均完播 33%**，榜首 41%，其余 36 / 33 / 29 / 27%，均值自洽。

这在真实实现里是数据层的活（同一份 `OpsStore` 读数，不在前端各算各的），不是画布上的活。

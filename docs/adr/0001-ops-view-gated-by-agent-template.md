# 运营视图只对 Sino 模板创建的工作区可见

运营视图不是 Chat 的全局功能，而是 **Sino**（内置运营 Agent 模板，`templateId: 'sino'`）创建的工作区才拥有的界面。判定依据是工作区本来就有的 `templateId` 字段，不新增任何绑定机制。

模板 id 用 `sino` 而不是 `ops`：模板名是 Agent 的人格名（与 `mino` 同一套命名法），`ops` 留给 CLI 命令面与 `ops/` 数据目录 —— 名字指的是"谁"，不是"哪个域"。

## Considered Options

- **全局视图**（所有 chat 都渲染运营视图）：违背"只在有运营上下文的会话里出现"，而且会给非运营会话塞进一份永远为空的运营视图。
- **给 session 新增模板来源字段**：与 `templateId` 重复表达同一件事，两个真相源迟早漂移。
- **`templateId: 'ops'`**：与 `hamuna ops` CLI、`ops/state.json` 混用同一个词，读代码时要靠上下文分辨"这是模板还是命令域"。人格名更不容易歧义。

## Consequences

- Chat 的渲染路径多一个 `templateId === 'sino'` 分支；非 Sino 模板创建的会话不渲染运营视图。
- **数据目录仍是 `ops/`，不改成 `sino/`**：数据是域的数据，不是某个 Agent 实例的私有物；换 Agent 人格不该换数据路径。
- 当前唯一来源是 Sino。等第二个模板也需要运营视图时，再把它升成模板自己声明的一项属性 —— 现在只有一个来源，先不为假想的第二个写抽象。
